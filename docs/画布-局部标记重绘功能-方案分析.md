# 画布「图像标记引用」功能 —— 方案分析

> 日期：2026-10-10（第 3 版，对齐 LibTV 无限画布）
> 状态：需求已锁定，改造中

---

## 一、需求定义（对齐 LibTV 无限画布）

**观感目标**：点一下图 → 提示词输入框里**立刻**出现一个引用小图标 → 点这个小图标**弹出下拉菜单** → 选"这个标记引用的是哪个内容"。

| 项 | 结论 |
|---|---|
| 触发 | 图片节点编辑栏的「标记」按钮 → 进入**画布级「元素选择模式」**（画布顶部蓝色提示条，**不弹任何卡片/面板**） |
| 选区动作 | **在画布任意图片上单击一次**（不是涂抹画笔） |
| 即时反馈 | 点击后**同步**插入引用 chip，**不等待网络**（这是"反应快"的来源） |
| 内容来源 | AI 识别，返回**多个候选**（3~5 个） |
| 下拉菜单 | 点 chip 弹出，列出候选，选中后 chip 更新为该内容 |
| 落地 | 选中的内容文字随提示词一起送给模型 |
| 图片范围 | **画布上任意含图节点**（不限连线关系）；进模式后画布**保持可平移**（便于移动找图），**节点拖拽禁用** |
| 模型来源 | 复用后台「无限画布智能体配置」 |

## 二、需求演进记录（防止返工）

| 轮次 | 用户口径 | 技术含义 | 结论 |
|---|---|---|---|
| 第 1 轮 | 局部元素引用到提示词，以小标签呈现 | 局部引用 | — |
| 第 2 轮 | 便签作为专属指令，只改框内、其余不变 | 局部重绘（inpaint），需 mask | 已否决 |
| 第 3 轮 | 不重绘，只采用标注范围内的东西 | 裁剪元素当参考 | 已被第 4 轮取代 |
| **第 4 轮** | **对齐 LibTV：点击 → 出小图标 → 点图标下拉选内容** | **点击标记 + AI 候选内容** | **最终方案** |

第 2 轮的重绘方向会引入 gpt-image-1 的 mask 依赖与按次费用；第 3 轮的裁剪方向需要涂抹操作。第 4 轮口径**最轻**：单击 + 图标 + 下拉选择。

## 三、关键技术判断

### 3.1 "零延迟"从哪来

点击 → chip 出现在提示词框是**纯前端同步操作**，不发任何网络请求，所以能做到毫秒级。AI 识别是**异步**进行的，结果只用于填充下拉菜单——用户点开菜单时结果通常已就绪。**任何"等 AI 返回再出图标"的设计都不可能快。**

### 3.2 一个坐标点对模型没有意义

只标记一个点，图像模型无法理解"这里是什么"。因此标记必须配上"内容"。本方案的内容来源是 **AI 识别出的文字**（下拉菜单里的候选）。

### 3.3 后台的必要性

| 环节 | 要后台吗 |
|---|---|
| 点击 → 出 chip → 点 chip 出下拉菜单 | **否**，纯前端 |
| AI 识别候选内容 | **是**（API Key 不能进浏览器，项目红线） |

## 四、复用后台「无限画布智能体配置」（不新建模块）

配置文件：`creative-agent-config.json` → `canvasAgent`（读取见 `server/index.js:2457`，写入接口 `/api/admin/creative-agent-config` 见 3981/3985 行）。

现有结构：

```
canvasAgent: {
  enabled, name, model, maxActions,
  prompt, personaPrompt, responseStyle, systemPrompt,
  capabilities: { createNode, createEdge, updateNode, moveNode, deleteNode, runGenerator },
  rules: { reuseNodes, askWhenUnclear, noQuotaWithoutRequest, verifyEachStep }
}
```

**复用方式（零新建）**：

1. `capabilities` 新增开关 `recognizeRegion`（默认 true，需同步修改 323-334 行的配置规范化逻辑，保证旧配置读得到默认值）
2. 尊重 `enabled` 总开关（关闭时不提供识别）
3. `model` 作为识别模型的首选（留空再走原有 provider 候选链）
4. 后台页面已存在，仅需多一个开关格子

**结论：不需要新建后台配置模块。**

## 五、数据模型

`promptParts` 沿用/扩展 element 类型：

```
{
  type: 'element',
  id: 'el-xxxx',
  nodeId: 'source-node-id',
  imageRef: 'output' | 'upstream',
  point: { x, y },            // 点击位置（原图像素坐标）
  thumb: 'data:image/png;base64,...',   // 以点击点为中心裁出的小块（上限 512px）
  content: '一只橘猫',         // 用户在下拉菜单里选定/修改的内容
  candidates: ['一只橘猫', '橘色毛发动物', '猫的头部特写']   // AI 候选
}
```

**兼容规则**：`inlinePromptParts()` 遇到未知 `type` 必须安全跳过；老画布不含 element 数据时，渲染外观必须与改造前**完全一致**。

## 六、功能链路

```
图片节点面板「标记」按钮
        ↓
进入标记态（禁用节点拖拽与平移）
        ↓
在图上单击一次
        ↓
[同步] 以点击点为中心裁小块图 → 提示词框光标处插入 chip（此时可显示"识别中"）
        ↓
[异步] 调识别接口 → 返回 3~5 个候选 → 填充 chip 的下拉菜单
        ↓
点 chip → 下拉菜单（Teleport 到 body，屏幕坐标定位）
        ↓
选中某项 → chip 更新为该内容
        ↓
点生成 → 内容文字并入提示词
```

降级：识别不可用（未配置 Key / 智能体开关关闭 / 网络失败）时，菜单候选为空，**不阻塞**，用户可手动填写内容。

## 七、影响面

| 文件 | 改动内容 |
|---|---|
| `src/views/CanvasStudio.vue` | 标记态交互由涂抹改为单击、以点为中心裁块、chip 下拉菜单、element 数据读写、生成时并入内容 |

**无数据库改动。后台页面仅需新增一个开关格子（复用现有接口）。**

**必须纳入验收**：图片节点 / 视频节点 / 生成配置节点**三处独立模板**均含提示词输入框，任一处漏挂 `:ref` 会导致功能静默失效——本项目已记录的踩坑类型。

## 八、验收标准（EARS）

| 编号 | 验收标准 | 优先级 |
|---|---|---|
| AC-01 | When 用户在标记态单击图上任意位置，系统必须**同步**在提示词框插入一个 chip，不等待任何网络请求 | P0 |
| AC-02 | While 单击完成，系统必须异步获取 3~5 个候选内容并填充下拉菜单 | P0 |
| AC-03 | When 用户点击 chip，系统必须弹出下拉菜单并展示候选 | P0 |
| AC-04 | When 用户选中某个候选，chip 必须更新为该内容，且该内容随提示词送模型 | P0 |
| AC-05 | If 识别不可用或失败，系统必须提示且允许手动填写，不阻塞流程 | P0 |
| AC-06 | While 老画布数据不含 element 类型，渲染外观必须与改造前完全一致 | P0 |
| AC-07 | While 处于标记态，节点拖拽与画布平移必须被禁用 | P1 |
| AC-08 | When 刷新画布重新载入，已标记内容必须仍可查看与编辑 | P1 |
| AC-09 | If 后台画布智能体被停用或关闭识别能力，系统必须不发起识别并给出说明 | P1 |

## 九、风险清单

| 风险 | 等级 | 说明与应对 |
|---|---|---|
| 识别模型不支持视觉 | 中 | 会在文本侧无法判定（模型可能瞎答）。**要求后台默认模型固定为可看图的（agnes-2.5-flash 已实测可用）**；由 AC-05 降级兜底 |
| 网络不稳定 | 中 | Agnes 上游抖动时走 502 分支。异步识别不阻塞主流程，属可接受 |
| 点击点周围裁多少 | 中 | 裁太小模型看不出，太大则不够"局部"。默认 240×240 需实测调整 |
| 三处模板漏改 | 中 | 已记录的踩坑类型，纳入 AC 逐项实测 |
| 老画布兼容 | 中 | 新字段必须可被旧渲染逻辑安全忽略 |
| 下拉菜单定位 | 低 | 画布有 transform，必须 Teleport 到 body + `getBoundingClientRect` 屏幕坐标 |
| `server/index.js` 体积 | 低 | 已 4632 行，远超单文件 300 行标准。本次只做增量，拆分另立技术债任务 |

## 十一、LibTV 截图确认的 UI 细节（第 4 版补充）

用户在 2026-10-10 提供了 LibTV 无限画布的真实截图，据此确认以下 UI 形态，**实现以截图为准**：

| 细节 | 截图所见 |
|---|---|
| 标记位置的可视化 | 图上被点击的位置显示**圆形徽标**（蓝色圆形 + 白色数字），编号从 1 递增 |
| 引用 chip 结构 | `小缩略图` + `编号` + `元素名称` + `下拉箭头`，例如 `1 扎马尾的女孩`、`2 黑色小狗` |
| 多标记共存 | 截图中有 1、2 两个标记，编号与图上徽标一一对应 |
| 元素名称来源 | AI 识别自动填充（截图中为「黑色小狗」），首选结果即默认值 |
| 下拉菜单用途 | 列出该位置相关的多个元素候选，**含同一对象的不同粒度**（用户举例："是黑狗还是黑狗身上的花裙子"） |
| 操作顺序 | ~~先在面板里选择图像，再在图像上点击要标记的位置~~ → **第 5 版修正**：点「标记」进入画布级「元素选择模式」（无面板），直接在画布上**任意含图节点**的图上点击标记；点「返回节点」退出并回到发起节点 |

**范围边界**：截图中输入框上方的快捷按钮（「反推提示词」「将小狗换成樱花树下的小猫」等）**不属于本次功能范围**；截图中的「Agent」下拉与发送按钮为 LibTV 原有界面，不涉及。
