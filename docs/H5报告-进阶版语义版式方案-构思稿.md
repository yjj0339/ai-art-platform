# H5 报告 · 进阶版语义版式方案（构思稿）

日期：2026-10-17
状态：**构思稿，未写一行代码，待确认后才进入实施**
范围：仅 `advanced`（进阶版）。不改 pro（高级版）三栏工作台链路、不改入门版/初级版、不改 5 个已发布内置模板、不迁移任何旧报告。

---

## 一、为什么是「进阶版」这个位置

核对当前真实配置（`server/data/h5-report-config.json`）：

| 版本 | status | rendererKey | 可用模板 | 学生端现状 |
| --- | --- | --- | --- | --- |
| junior 初级版 | unconfigured | 空 | 无 | 未开放 |
| starter 入门版 | enabled | starter-simple | 1 套（kids-classroom） | 已开放，极简三问 |
| **advanced 进阶版** | **unconfigured** | **空** | **无** | **未开放** |
| pro 高级版 | enabled | pro-workbench | 4 套 | 已开放，三栏工作台 |

结论：进阶版是**空白版本**。对它做新引擎，等于新开一条通道，而不是替换既有功能：

- 没有存量报告要兼容（不存在进阶版的历史快照）
- 不需要迁就 pro 的绝对坐标模板结构
- 出问题把 `rendererKey` 清回空，就退回到「进阶版未开放」，零影响其他版本
- 家长从未见过进阶版报告，首套模板的质量直接决定第一印象 —— 这是本方案唯一真正的风险点

---

## 二、现有链路为什么不适合直接搬给进阶版

pro 的链路（结构化文案 → 绝对坐标模板 → 填元素 → 可选 AI 挪坐标 → 存快照）存在这些硬约束：

| 问题 | 证据 | 对进阶版的影响 |
| --- | --- | --- |
| 模板是死的 1080×1920，正文变长就只能逐字切成续页 | `src/utils/h5Layout.js` `splitH5Text` | 进阶版学员文案普遍比 pro 短，会出现大量「3 行正文 + 一整页空白图区」的松垮页面 |
| 溢出靠估算而非测量 | `estimateH5TextHeight` | 中文/英文/标点混排误判，预览与确认不一致 |
| 图片放不下会自动追加「只有图没有正文」的页 | `compileH5Layout` 的 `-images-` 分支 | 页面语义散架，家长看到的是图片堆 |
| AI 排版只返回 x/y/w/h | `server/h5-layout.js` 的 prompt | 60 秒超时、每分钟 6 次限流，换来的是「AI 帮忙拖框」 |
| 模板制作要手工摆 56 个绝对坐标元素 | 后台 1 号编辑器 | 一套模板 2-3 小时，运营做 5 套就要一周 |
| 正文框太小时报「请先调整模板」 | `h5Layout.js:142` | 学生没有模板编辑权，直接卡死 |

进阶版学员年龄更小、记录更少、文案更短，**该被解决的问题不是「排得花」，而是「少量内容也能不空洞地成篇」**。现有引擎恰好最不擅长这个。

## 三、方案主线：内容与视觉解耦，四层分工

```
内容层（结构化 blocks）
   → 编排层（AI 或规则：选版式、定分页、配图）
      → 版式层（自适应 Vue 组件，自己算尺寸）
         → 装饰层（绝对定位，但只许装饰，永久在内容之下）
            → 单一 DOM 渲染（预览 / 分享 / 海报 / 导出同源）
```

一句话：**AI 从「拖框工人」变成「版面编辑」；模板从「存坐标」变成「存版式族 + 主题 Token」。**

### 3.1 内容层：report-doc v1

章节收敛为 6 个（不是照搬 pro 的 8 章）。理由：进阶版的作品过程记录完整度更低，8 章必然有 3-4 章靠套话填满，而套话正是「AI 模板味」的根源。

| 章节 | 语义 | 缺失时 |
| --- | --- | --- |
| `cover` 我的作品 | 标题 + 最终作品 + 一句介绍 | 必备，无图时提示先选最终作品 |
| `idea` 我想做什么 | 灵感来源 / 想解决的问题（合并） | 有文字即可成页 |
| `process` 我是怎么做的 | 草图、步骤、修改前后 | 无草图则整章跳过，不补空页 |
| `try` 我试了几种 | 仅当作品版本 ≥2 时出现 | 版本 <2 直接不出这章 |
| `best` 我选了这个 | 最终选择 + 选择理由 | 无理由时只描述可核对的变化，不编造 |
| `grow` 我的收获 | 反思 / 老师的话 | 无反思则跳过 |

内容单元是 **block**，共 6 种：

```json
{
  "version": 1,
  "chapters": [
    {
      "id": "process",
      "title": "我是怎么做的",
      "blocks": [
        { "id": "b1", "type": "compare", "labels": ["最初画的", "改过的"], "images": ["asset:sketch", "asset:refined"] },
        { "id": "b2", "type": "note", "text": "我把屋顶改成了斜的，因为斜的更能接住雨水。", "source": "student" }
      ]
    }
  ]
}
```

block 类型：`heading` / `body` / `note` / `compare`（2 图对照）/ `collage`（1-3 图）/ `steps`（3-5 条图文时间线）。

每个 block 带 `source` 字段（`student` / `recorded` / `ai`）。用于两件事：AI 不得改写 `student` 原文的事实；渲染时可标注哪些是孩子自己写的。

### 3.2 编排层：AI 出「计划」，不出坐标

AI 输出：

```json
{
  "plan": [
    { "chapter": "cover",   "layout": "hero",     "images": ["asset:final"] },
    { "chapter": "idea",    "layout": "collage-2","images": ["asset:ref1", "asset:sketch"] },
    { "chapter": "process", "layout": "compare",  "images": ["asset:sketch", "asset:refined"] },
    { "chapter": "best",    "layout": "split",    "images": ["asset:final"] }
  ],
  "warnings": ["本章只有 1 张参考图，已降级为单图版式"]
}
```

约束（由程序强制，不信 AI 自觉）：

- 只能引用输入里存在的 `chapter` / `layout` / `asset` 标识，引用不存在 → 整份拒绝，回退规则引擎
- 不能新增、删除、改写文字内容；`trim` 只允许指定「压缩到多少字」，原文另存
- 每页必须满足所选版式的容量契约，超了由程序换版式或拆页，而不是缩字号
- 无 AI / AI 失败 / 超时 → 规则引擎接管：按「图数 + 字数」直接选版式（`0 图 → note`、`1 图 → split`、`2 图 → compare`、`3 图 → collage-3`），报告照样出得来

费用与稳定性：**每份报告最多 1 次 AI 调用**，结果按 `(内容版本, 模板版本)` 缓存；换模板不重复计费（沿用现有 `organizedContentCache` 思路）。比现在「每次生成都可能调一次 AI 排版」更省。

### 3.3 版式层：8 个自适应组件 + 容量契约

| 版式 ID | 容量契约 | 典型用途 |
| --- | --- | --- |
| `hero` | 标题 ≤14 字 + 1 图 + 正文 ≤80 字 | 封面、最终作品 |
| `split` | 1 图 + 正文 ≤120 字 | 图文左右，最通用 |
| `collage-2` | 2 图 + 标题 + ≤60 字 | 灵感、两张对照 |
| `collage-3` | 3 图 + 标题 | 多个方案 |
| `compare` | 2 图 + 2 标签 + ≤60 字 | 修改前后 |
| `steps` | 3-5 条（图 + 一句 ≤20 字） | 创作过程 |
| `note` | 正文 ≤200 字，无图 | 纯文字章 |
| `quote` | 一句话 ≤40 字 | 收获、金句 |

关键点：**尺寸由 CSS Grid / Flex 自己算，模板里不存任何 x/y**。所以：

- 永远不会溢出，不需要逐字切分
- 不需要 `estimateH5TextHeight` 估算，文字用真实 DOM 测量
- 窄屏自适应，不需要等比缩放一张 1080 宽的画布
- 改一个字即时生效，不需要重新出图

### 3.4 装饰层：保留手账质感，但只许装饰

胶带、便签、纸张纹理、贴纸仍是绝对定位（这是质感来源），但受三条硬约束：

1. 只允许 `role: decor`，不得承载任何文字/图片内容
2. 渲染时永远在内容区之下，且不得进入版式声明的「保护矩形」
3. 装饰不参与 AI 编排，AI 无法移动或删除

这样「好看」和「内容能变长」不再互相伤害。

### 3.5 输出形态

| 形态 | 说明 |
| --- | --- |
| H5 分享页 | 与预览同一份 DOM，手机打开即读 |
| 长图导出 | 由浏览器一次性合成，**仅作为导出产物**，不作为报告本体 |
| 分享海报 | 沿用现有海报链路与二维码 |
| PDF | 同一 DOM 走打印样式，用于存档/打印 |

文字是真文本 → 可选中、可搜索、可无障碍朗读。这是与现在「产品设计故事整页截图」路径最大的分野。

## 四、后台模板生产（进阶版专用轻编辑器）

不做绝对坐标画布。管理员只做三件事：

1. **选主题包**：6 色配色 + 2 种中文字体 + 纸张纹理 + 装饰素材组
2. **勾章节与版式**：启用哪 6 章、每章允许哪几个版式（决定编排自由度）
3. **上传装饰素材**：PNG（胶带/便签/贴纸），声明安全区

工作量对比：

| | 现在（1 号编辑器） | 本方案 |
| --- | --- | --- |
| 一套 8 页模板 | 摆 56 个绝对坐标元素 + 逐个锁定/图层，2-3 小时 | 选主题 + 勾章节 + 传装饰，15-20 分钟 |
| 加一套新风格 | 重摆一套坐标 | 换主题包 |
| 加一个章节类型 | 改 `H5_CHAPTERS` 代码 | 配置里勾选 |

## 五、实施顺序（5 步，每步独立可验收）

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| S1 | report-doc 模型 + 规则编排 + `hero/split/note` 3 个版式 | **无 AI、无网络**也能从真实项目生成 3-6 页报告并在手机预览 |
| S2 | 补齐 8 版式 + 真机窄屏阅读 | 390 宽下正文 ≥14px、无横向滚动、文字可选中 |
| S3 | 接入 AI 编排（计划式） | 一次受控真实成功调用 + 失败注入回退规则引擎 |
| S4 | 后台主题包配置页 + 首套模板「清新水彩」 | 管理员 20 分钟内做出并发布一套模板 |
| S5 | 开放进阶版 | `editions.advanced` 配 `rendererKey: flow-v2` + 模板授权；审核/发布/分享/海报回归通过 |

S1 是整条路的地板：**先把「不靠 AI 也能出一份不空洞的报告」做出来**，再谈 AI 加持。这样即使模型不可用，进阶版也能开放。

## 六、验收口径（进阶版 6 条硬指标）

1. 只有 1 张作品、零文案的项目，能出 3 页以上且**不出现**「我保存了 N 个作品版本」这类套话
2. 200 字长文案 + 1 张竖图：自动拆页，无溢出、无报错、无「请先调整模板」
3. 断网或未配置模型时仍能生成并预览（标注「未使用 AI 编排」，不得标记为 AI 成果）
4. 同一内容换模板：编排结果复用，不重复计费
5. 手机 390 宽：正文 ≥14px、注释 ≥12px、无横向滚动、文字可选中可搜索
6. 把 `rendererKey` 清空即回到「进阶版未开放」，其他三个版本行为完全不变

## 七、明确不做（本方案边界）

| 不做 | 原因 |
| --- | --- |
| 改造 pro 的三栏工作台 | 另一条已验收链路，改动风险与收益不匹配 |
| 迁移或改写任何旧报告快照 | 无必要，旧报告继续按自己的快照渲染 |
| 自由拖拽编辑器 | 已验证成本过高，且是模板崩坏的根源 |
| 每页 AI 生图 | 中文文字不可控，单份成本高，改一个字要重出图 |
| 无限画布工作流（方案 C） | 仍处测试态，本方案不依赖也不改变它 |
| 学生自由编辑版式 | 进阶版学员应「选模板 + 确认内容」，不碰排版 |

## 八、风险与待确认

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 首套模板的视觉质量 | 家长第一次看到进阶版报告，好看与否决定口碑 | 首套只做 1 套但做精；先出 3 个版式的视觉样张给你和教学主管过目 |
| 版式组件是新的视觉资产 | 需要设计投入，我可以给结构与交互，但「好看」需要设计把关 | S1 先做骨架，S2 与设计师对齐视觉 |
| 两套章节字典并存（6 章 vs 8 章） | 后台管理员可能混淆 | 模板上明确标注「适用版本 + 章节模型」 |
| 进阶版从未开放 | 没有真实学生数据验证假设 | S1 用 3 个真实项目（少素材/长文案/多版本各一）先跑 |

**待你确认**：若你说的「高级版本」其实指 pro 那张三栏工作台（`pro-workbench`），插入点和迁移策略要重写 —— pro 有 4 套已授权模板和若干草稿，不能像进阶版这样从白纸开始。请确认一句即可。

## 九、与既有决策的关系

本方案不推翻《决策 001：学生报告优先采用 H5》与《决策 016：H5 模板增加管理员受限可视化排版》。决策 016 的「受限元素编辑」在 pro 上继续有效；本方案是给进阶版新增的**第二种模板范式（语义版式）**，两者并存，靠模板字段区分：

- `engine: 'absolute-v1'`（现有，`designDocument`）→ pro 继续用
- `engine: 'flow-v2'`（本方案）→ 进阶版用

若确认推进，需在《技术决策记录》新增一条决策，并同步《功能基线与回归清单》。
