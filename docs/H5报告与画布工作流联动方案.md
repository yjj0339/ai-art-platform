# H5 报告页 与 后台无限画布工作流 联动方案

> 状态：方案待确认（代码未改动）
> 日期：2026-11-06
> 适用：学生端 `/student/h5-report` 与后台「报告工作流库」

---

## 一、一句话说清

学生在 H5 报告页把图片和自述填好，点一下生成，这些内容就**按格子送进后台画布上对应的节点**，画布按老师配好的流程跑完，产出的图回到学生的报告预览里。

学生不用懂工作流，老师不用在后台替学生传图。

---

## 二、现在是什么状况

| 位置 | 现状 |
| --- | --- |
| 学生端 H5 报告页 | 左栏「创作素材」自动聚合当前项目的图，学生不能挑选；右栏风格卡读的是**前端写死的模板库** |
| 后台报告工作流库 | 老师搭的画布工作流，有节点、有提示词、有封面 |
| 两者关系 | **两本互不相通的册子**。后台改什么，学生端都不跟着变 |
| 点生成时 | 服务端只把图当参考图，调用**一次**出图，返回最多 4 张 |

所以现在的"联动"是假的：学生看到的风格不是后台配的，后台配的工作流只被当成"一次出图的参考图源"。

---

## 三、已确认的设计定案

| 决策点 | 结论 | 原因 |
| --- | --- | --- |
| 素材怎么进工作流 | **第 N 张图对应第 N 个图像节点**，一对一绑定，不是打包塞进第一个节点 | 老师能精确控制每一页用什么图 |
| 文字怎么进工作流 | 学生写的「创作自述」进**文字节点** | 让报告文案贴着学生自己说的话 |
| 出图形态 | **整块图**，一页就是一张完整画面（含中文） | 火山引擎实测可出中文，不需要再叠文字层 |
| 章节从哪来 | 跟着工作流的出图节点走：后台有几个出图节点，学生就有几块可勾 | 后台加一个节点，学生端自动多一页，两边永远对得上 |
| 结果去向 | 汇总到结果节点，按顺序回到学生端 H5 报告预览 | 学生点完就能看到成品 |
| 老师怎么搭节点 | **新建时只铺 1 个图像节点 + 1 个文字节点 + 1 个结果节点，要几页自己加** | 不预设页数，灵活度最高 |
| 图像框与节点怎么对 | **按画布上从上到下的位置**：最上面的图像节点 = 学生端第 1 个图像框 | 老师本来就从上往下排页序，符合直觉；且不依赖节点 id，加删节点、复制模板都不会失效 |
| 学生端框数 | **跟着图像节点数走**，不写死 12 | 老师摆 6 个节点就 6 个框，摆 12 个就 12 个 |
| 要不要做配置编辑器 | **不做完整编辑器**，只在节点上留一个可选的下拉/数字，用于打乱顺序时覆盖默认 | 完整编辑器成本高，且复制模板、删除节点会让绑定悬空 |

## 三·补一 方案1（配置编辑器）vs 方案2（节点天生对应）

### 两个方案在说什么

| | 方案1：编辑器 | 方案2：节点天生对应 |
| --- | --- | --- |
| 老师怎么建模板 | 先把完整节点搭好 | 新建时自动铺 1 图像 + 1 文字 + 1 结果节点，老师自己复制扩展 |
| 怎么指定对应关系 | 打开编辑器，逐个下拉「这个节点 → 第几框」 | 不用指定，**画布上从上往下第 N 个图像节点就是第 N 框** |
| 学生选模板点生成 | 按编辑器里的配置填 | 按位置自动填 |
| 老师要做几次 | 每搭一条模板选十几次以上 | 0 次 |

### 方案1 的真实代价

| 问题 | 后果 |
| --- | --- |
| 复制模板 | 节点 id 全部重新生成，原来的绑定全指向不存在的节点 → 学生页空白 |
| 删除节点 | 绑定悬空，运行时报错，得手动回去清 |
| 改一次结构 | 前面选的十几项要重选一遍 |
| 谁承担 | 这些错**不是开发承担，是日后每个改模板的老师承担** |

方案1 唯一的收益是「可以任意指定顺序，不必按上下排」。但画布上老师本来就是从上往下摆页序，这个收益基本用不上。

### 结论：走方案2

方案2 + 位置即对应，两个老问题（复制失效、删节点悬空）从根上消失，因为**不依赖任何 id，也不存任何配置**。

但保留一个「半个编辑器」：节点属性面板里显示一行只读的「对应第 3 个图像框」，旁边一个可选数字框。只在老师想打乱顺序时填。**平时不碰，坏了也能自己看明白。**

### 方案2 需要补的两块（不做就落不了地）

| 补什么 | 为什么 |
| --- | --- |
| 新建模板时自动铺骨架节点 | 老师不用记要摆几个、摆什么类型；学生端框数永远等于图像节点数 |
| 节点上显示「第 N 框」 | 老师搭完就能一眼核对，不用点进属性面板 |

### 结果回传的顺序

结果节点汇总到的图，按**图像节点的顺序**（不是执行完成的先后）回传学生端。否则 12 页的封面可能变成第 9 页。这条必须在服务端固定，不能交给并发顺序。

## 三·补三 节点上的「H5 用途」下拉（替代编辑器）

### 为什么需要它：现在这个信息是藏起来的

现在「哪个节点收学生自述」由 `configuration.studentPage.blocks[].binding` 决定——**一份看不见的配置，只在编辑器里能改**。老师搭完画布完全不知道自己写的那个文字节点到底有没有接上学生。

所以这个下拉不是新增概念，是**把已经存在、但看不见的东西搬到节点上**。

而且它解决了一个「按类型自动认」认不出来的坑：画布上的文字节点有两种用途——

| 文字节点的两种用法 | 自动认会怎么错 |
| --- | --- |
| 老师写死的提示词，学生看不见 | 被当成"学生自述框"，学生一句话顶掉老师整段模板 |
| 学生自己填的自述 | 认对了 |

两种在画布上长得一模一样，都是 text 节点。**只有老师自己知道是哪种**，所以必须能标。

### 下拉的取值（4 个，不多做）

| 取值 | 含义 | 学生端表现 |
| --- | --- | --- |
| 图像素材 | 学生传图进这个节点 | 生成一个图像框，第 N 框按上下顺序 |
| 文字素材 | 学生自述填进这个节点 | 生成文字框（多个时用最上面那个） |
| 结果返回 | 汇总成品 | 收集成品，按节点顺序回传报告预览 |
| 不上前端 | 老师内部用 | 学生端看不见 |

### 默认值怎么给（关键：老师 90% 不用动）

| 节点类型 | 默认取值 |
| --- | --- |
| image | 图像素材 |
| result | 结果返回 |
| text / prompt | 不上前端（**故意保守**：宁可少接，也不能让学生的自述顶掉老师写死的提示词） |
| 骨架里预置的那个文字节点 | 文字素材（我们铺的，我们说了算） |

所以：**新建的模板出厂即正确，零配置就能跑**；只有存量模板、或者老师自己复制文字节点时要手动点一次。

### 顺序仍然由位置决定，不用填数字

- 下拉只管「这是什么」，**不管「是第几」**
- 同一类节点里，按画布从上到下自动编号
- 节点上直接显示「图像 3」「文字 ~」「结果」这样的角标

这样老师只有一个动作（选种类），不会同时管"种类"和"序号"两件事。

### 配套：发布前的「学生端预览」核对条

后台顺手显示一行，老师一眼核对：

```
学生端将显示：12 个图像框 · 1 个文字框 · 1 个结果
```

比报错友好，也比让老师去数节点靠谱。数字不对就说明有节点忘标了。

## 三·补二 为什么最初不做「配置编辑器」

曾考虑过做一套界面，让老师逐个下拉选择「这个节点对应第几个图像框」。评估后不适合：

| 问题 | 说明 |
| --- | --- |
| 复制模板会失效 | 老师复制一条模板改一改，节点 id 全部重新生成，原来的绑定全指向不存在的节点，学生页直接空白 |
| 删节点会留空绑定 | 画布上删掉一个节点，对应绑定要手动清理，否则运行时报错 |
| 操作负担 | 每搭一条模板要选 12 次以上，且改一次结构要重选一遍 |

改为「位置即对应」后，这两个问题从根上消失，因为不依赖任何 id。只在需要打乱顺序时，用节点上的一个可选数字覆盖即可。

## 四、结构长什么样

画布必须是**并列分支**，不是一串糖葫芦：

```
图 1  ──→  出图节点 1  ┐
图 2  ──→  出图节点 2  ├──→  结果节点  ──→  学生端报告预览
  …                    │
图 12 ──→  出图节点 12 ┤
自述  ──→  文字节点     ┘
```

**为什么不能串成一条链**：图会沿连线层层往下传。第 10 个节点会收到前面 9 张图，再加上自己的，超过上限后被截断，后面的页就用不上自己的图了。

## 五、三块工作

### 第 1 块：后台按位置自动对应（不做配置编辑器）

服务端本来有一套按 id 绑定的机制（`configuration.studentPage.blocks` 的 `binding` 字段），但它要求老师逐个下拉选择，且复制模板、删除节点会让绑定悬空。**本方案不用它，改为按画布位置自动对应。**

| 项 | 内容 |
| --- | --- |
| 对应规则 | 出图节点按画布上从上到下的位置排序，第 N 个 = 学生端第 N 个图像框 |
| 文字节点 | 固定收自述，画布上有多个文字节点时取最上面那个 |
| 结果节点 | 按类型识别（`result`），不参与排序 |
| 覆盖率 | 无需任何配置，老师搭完即可用 |
| 顺序覆盖 | 节点属性里留一个可选数字「对应第几个图像框」，仅在需要打乱顺序时填 |
| 校验 | 发布前检查：至少 1 个出图节点；出图节点数与学生端框数自动对齐，不需要人工核对 |

### 第 2 块：学生端按节点数显示图像框

现在左栏显示的是写死的分组（草图 / AI 版本 / 参考图），要改成按工作流的出图节点数量生成。

| 项 | 内容 |
| --- | --- |
| 图像框数量 | 等于该工作流的出图节点数，老师加节点就多一个框 |
| 默认填入 | 项目里已有的图按顺序自动填进框，学生可以换、可以清空 |
| 文字自述框 | 一个多行输入框，默认带入现有的创作自述，可改 |
| 提交结构 | 改成按框的序号提交（第 1 框、第 2 框…），而不是现在这种分组结构 |
| 空框处理 | 学生没填的框直接跳过，对应节点不跑 |

### 第 3 块：服务端按节点跑

| 项 | 内容 |
| --- | --- |
| 执行方式 | 用现成的节点规划逻辑，按拓扑顺序逐个节点调模型，不再只调一次 |
| 每个节点的输入 | 只吃绑定到自己这个格子的图，不吃别节点的 |
| 结果收集 | 所有出图节点的结果汇总，按节点顺序返回 |
| 进度回报 | 每跑完一个节点回报一次，前端显示「第 3/12 页出图中」 |
| 失败处理 | 某个节点失败时保留已成功的，返回明确提示；不整份丢弃 |

三块的依赖关系：**第 1 块不做，第 2 块没有依据，第 3 块没有数据来源。**

## 六、数据结构（给开发看）

不需要新增配置字段。对应关系在运行时从画布节点推导：

```
出图节点排序 = 所有 type ∈ {image, video} 的节点
              按 position.y 升序（同高时按 position.x 升序）
第 N 个出图节点 ⇄ 学生端第 N 个图像框
```

节点上只有一个可选覆盖字段：

```json
{
  "id": "node-x7k2",
  "type": "image",
  "position": { "x": 320, "y": 180 },
  "data": {
    "prompt": "封面：水彩风格的城市清晨，整体暖调，画面中不要出现文字",
    "slot": 1
  }
}
```

- `position` 服务端已在规范化时保留（`ai-skill-store.js` 的 `position: {x, y}`），可直接用于排序
- `data.slot` 是可选字段，填了就以它为准，不填则按位置顺序
- `type: "result"` 的节点不参与排序，只做汇总
- 文字节点取 `type ∈ {prompt, text, note}` 中最靠上的一个

学生端点生成时提交的数据，从现在按分组（`sketchOriginal` / `versions` / `referenceImages`）改成按框序号：

```json
{
  "workflowId": "...",
  "workflowVersion": 3,
  "frames": [
    { "index": 1, "url": "https://.../1.jpg" },
    { "index": 2, "url": "https://.../2.jpg" },
    { "index": 3, "url": "" }
  ],
  "statement": "我画的是下雨天的城市，因为……"
}
```

- `frames` 按顺序对应排序后的出图节点；`url` 为空的框直接跳过，对应节点不执行
- 执行器需要一个小改动：现在生成节点会取 `upstreamImages`（上游传下来的图），并列结构下需要确保每个节点只吃自己那一张

## 七、老师搭工作流时要遵守的三条

这部分是给配置工作流的人看的，不遵守会出问题：

1. **出图节点并列接结果节点**，不要串成一条链。
2. **从上到下按页序摆**：最上面的图像节点对学生的第 1 个图像框，往下依次是第 2、3…页。想打乱就在节点属性里填「对应第几框」。
3. **提示词要写清这一页画什么**。节点越多，每段提示词越要具体，否则多页会长得很像。

## 八、代价与风险

| 项 | 情况 |
| --- | --- |
| 时间 | 12 个节点串行，每张约 10 秒，一份报告 **2 分钟起步**。学生必须看到进度，不能干等 |
| 并发 | 同时跑 3 个可压到 40 秒左右，但同供应商并发高了容易限流报错，需实测 |
| 费用 | 一份报告 = 12 次以上出图 + 1 次文字，是现在的数倍。后台「每日次数」限额必须真正启用 |
| 断线 | 跑两分钟，中途关页面会丢结果。要么服务端排队后台跑，要么至少做到刷新后还能看进度 |
| 空白图像框 | 学生没填的框，对应节点**直接跳过**（已确认：没关系，跳过即可） |
