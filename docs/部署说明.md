# 部署说明

## 部署原则

服务器只部署运行代码和必要配置，不上传本地依赖、测试产物、日志或开发工具文件。

## 必须包含

- `src`、`public`、`server`、`scripts`
- `package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`、`vite.config.js`、`index.html`
- `.env.example`、`server/.env.example`，仅用作服务器环境变量配置参考

## 不应上传

- `node_modules`：在服务器执行 `pnpm install --frozen-lockfile` 重新安装。
- `test-results`：本地测试截图和报告。
- `logs`、`*.log`：本地运行日志。
- `.git`、`.codex`、`.vscode`：版本控制、Codex 和编辑器配置。
- `docs`、`subtasks`、`AGENTS.md`：项目资料与开发规则，不参与运行。
- `.env.local`、`server/.env`：本地或服务器私密配置，不能作为代码包上传或提交。

## 服务端持久化数据

`server/data` 不是缓存，当前包含课程 PDF、课程视频和后台模型、报告配置。部署时不要把它作为代码目录的一部分覆盖或删除。

服务器应配置独立且可写的持久化目录，例如：

```text
AI_DATA_DIR=/var/lib/project-005-ai-art/data
```

首次部署时，将需要保留的 `server/data` 内容迁移到该目录；以后发布新代码时保留该目录不动，并定期备份。

## 发布顺序

1. 上传运行代码，不上传“部署说明”中的排除内容。
2. 在服务器配置 API 密钥、端口、`AI_DATA_DIR` 等环境变量。
3. 执行 `pnpm install --frozen-lockfile` 安装依赖。
4. 执行 `pnpm build` 生成 `dist`。
5. 启动 `server/index.js`，并确认服务进程对 `AI_DATA_DIR` 有读写权限。
6. 验证登录、课程资源读取、AI 接口和报告生成等主要功能。

## 端口、反向代理与正式环境配置（2026-11-26 补充）

### 端口

| 场景 | 后端 | 前端 | 说明 |
|---|---|---|---|
| 本机开发 `pnpm dev` | `127.0.0.1:3000` | `5173`（Vite） | Vite 把 `/api` 转发到后端；`scripts/dev.mjs` 支持 `--server-port`、`--web-port`、`--host` |
| 正式环境 | `127.0.0.1:3000`（`PORT` 可改） | 由 Nginx 提供 `dist` | 后端只监听本机，不直接对外，也不提供前端页面 |

正式环境的结构：访客 → Nginx（HTTPS，提供 `pnpm build` 生成的 `dist`）→ `/api/` 转发到 `http://127.0.0.1:3000`。

### Nginx 示例

```nginx
server {
  listen 443 ssl http2;
  server_name art.example.com;            # 换成实际域名
  # ssl_certificate / ssl_certificate_key 按实际证书填写

  root /srv/project-005-ai-art/dist;      # pnpm build 生成的目录
  index index.html;

  # 前端是 history 路由：刷新任意页面都回到 index.html
  location / {
    try_files $uri $uri/ /index.html;
  }

  location /api/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    # 配合 server/.env 的 TRUST_PROXY=true，后端才能拿到访客真实 IP（登录保护按网络计数）
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    # AI 出图等上游请求最长等 3 分钟；AI 伙伴的流式回复每 15 秒有心跳，并已自带 X-Accel-Buffering: no
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
    # 普通接口上限 80MB，PPT 课件转换 128MB
    client_max_body_size 130m;
  }

  # 课程视频按 base64 上传：512MB 的视频请求体约 683MB
  location = /api/course-video/upload {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 600s;
    proxy_send_timeout 600s;
    client_max_body_size 700m;
  }
}

server {
  listen 80;
  server_name art.example.com;
  return 301 https://$host$request_uri;
}
```

Nginx 前面如果还有 CDN 或云负载均衡，`$remote_addr` 是它们的地址，需要按其文档用 Nginx `real_ip` 模块还原访客 IP，否则所有访客仍会被当成同一个 IP。

### 正式环境必须设置

`server/.env`：

- `NODE_ENV=production`：启动时检查下面几项，缺少就拒绝启动。
- `AUTH_MODE=server`、`DATABASE_URL`、`SESSION_COOKIE_SECURE=true`、`AI_DATA_DIR`（独立的持久化目录）。
- `APP_ORIGIN=https://实际域名`：必须和浏览器地址栏里的来源完全一致（含 https、不带路径），否则保存类接口会被来源校验拦截；多个来源用英文逗号分隔。
- `TRUST_PROXY=true`：前面是本机 Nginx 时必须开；不开的话启动日志会提醒，所有访客会被当成同一个 IP，登录保护可能把所有人一起锁住。
- `RISK_HASH_SECRET`、`AI_CREDENTIAL_ENCRYPTION_KEY`：各填一串随机字符，设置后不要再改（后者改了需要在后台重新填写腾讯混元 3D 凭据）。

前端构建环境（项目根目录 `.env` 或 `.env.production`）：`VITE_AUTH_MODE=server`；`VITE_ORGANIZATION_CODE` 可填默认机构代码，登录页会预先填好。

其余可选项（登录保护阈值、文字模型、上传上限、课件转换工具路径等）见 `server/.env.example` 里的说明。

### 登录保护：网络锁定与机构代码（2026-11-26）

- 网络（出口 IP）失败计数改为按「要登录的机构」分开记：A 校的失败不会锁住 B 校；机构代码不存在的都算进同一个「未知机构」计数，乱填机构代码绕不开。
- 同一网络里每个账号登录成功一次（同一账号每 15 分钟最多一次）抵扣 3 次失败（`LOGIN_IP_SUCCESS_CREDIT`），全班共用一个出口 IP 时，偶尔输错不会把全班锁住；攻击者用自己的一个账号反复登录也刷不掉计数。
- 净失败达到 `LOGIN_IP_MAX_FAILURES`（默认 50）时整个网络暂停登录 `LOGIN_LOCK_MINUTES`（默认 15）分钟，提示里会说明是「这个网络」并告诉用户找管理员。管理员在后台「账号安全 → 登录锁定」里能看到被锁的网络（只显示 IP 前两段，如 `183.21.*.*`）并一键解除，只能看到、解除自己机构的；解除写审计日志。
- 账号锁定规则不变（同一账号连续输错 5 次，锁定 1、2、4… 分钟，最长 15 分钟）。
- 登录时机构代码不再区分大小写（平板输入法常把首字母自动变大写）。
- 数据库：`login_attempts` 新增 `ip_hint` 列，新增 `login_ip_credits` 表，都在 `server/risk-schema.sql` 里，后端第一次处理登录时自动补上（`pnpm db:migrate` 也会建）。旧数据兼容；升级前的网络计数按旧规则存的，自然失效后一天内自动清理。
- 回退：换回旧代码即可，多出来的列和表旧代码不会读，不影响登录。
- 验证（2026-11-26，本机隔离测试环境，不涉及 AI 调用）：登录保护专项 33 项（班级共用网络的抵扣、攻击锁定、机构之间隔离、管理员查看和解除、权限、清理）、代理提醒 6 项、生产模式启动提醒，以及原有风控回归 52 项，全部通过；后台「账号安全 → 登录锁定」页面实际点击解除也已验证。线上 Nginx 环境未验证，上线后请按上面的配置核对一次。
