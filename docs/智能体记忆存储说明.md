# 学生端智能体记忆存储说明

> 一句话：一个学生账号只有一份记忆，AI 绘画 / 视频 / 3D / 课程 / 报告五个页面共用，**存在服务器**（现在跑在你自己的电脑上），不存浏览器。换页面、刷新、换设备登录都能接着上次聊。
>
> **账号之间彻底隔离**：一个账号一个文件，A 的对话在物理上不可能出现在 B 那里。

## 1. 文件在哪

| 运行环境 | 实际位置 |
|---|---|
| 现在（你电脑本地） | 目录 `server/data/agent-memory/`，里面一个账号一个 `.json` 文件 |
| 上架到服务器后 | 同一个相对位置；如果服务器设置了 `AI_DATA_DIR` 环境变量，就跟随它（建议指向持久化数据盘，例如 `/data/canvas-studio`） |

目录长这样（文件名前半段是账号 ID 方便运维认人，后半段是哈希保证不撞车）：

```text
server/data/agent-memory/
├── 3c9f1e7a-....json        ← 学生甲的对话（就是「甲的智能体记忆存储文档」）
├── 7b2d4f88-....json        ← 学生乙的对话
└── ...
```

想清空某个学生的记忆，删掉他那个文件也行（但更推荐让他点面板上的「清空」按钮，那样会同时刷新页面）。

## 2. 一个文件长什么样

```json
{
  "version": 2,
  "userId": "3c9f1e7a-...",
  "userName": "测试2",
  "organizationId": "demo-school",
  "updatedAt": "2026-11-14T07:05:55.203Z",
  "messages": [
    { "id": "mwg26zi9-b945bc7a", "role": "student", "content": "我想画一只会飞的鲸鱼", "page": "paint", "at": "2026-11-14T07:03:08.865Z" },
    { "id": "mwg26zjn-133e1e61", "role": "agent", "content": "好，鲸鱼在天上，云做背景", "page": "paint", "at": "2026-11-14T07:03:08.916Z" }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `userId` | 这个文件属于哪个账号（读的时候会再核对一次，见第 3 节） |
| `role` | `student` = 学生说的；`agent` = 老师说的 |
| `content` | 原话，最多 2000 字 |
| `page` | 这句是在哪个页面说的：`paint` / `video` / `model3d` / `course` / `report` |
| `at` | 记录时间 |
| `messages` | 每个账号最多留 400 句（约 200 轮），超了自动丢最早的 |

**没写进记忆的东西**：页面顶部那句固定的问候语、以及「老师这会儿没听清」这类报错提示（属于这一次没成功，不是记忆）。

## 3. 账号隔离是怎么做的（三层保险）

不做「大家挤在一个文件里按 ID 分组」，那样一个写错就全串。现在是三层：

**第一层：物理隔离。** 一个账号一个文件。甲的对话和乙的对话根本不在同一个地方，读写互不影响。顺带解决了上架后的性能问题——说一句话只重写自己那份几十 KB 的小文件，不是重写一个几百 MB 的大文件。

**第二层：文件名不会撞。** 文件名 = `净化后的账号ID` + `账号ID 的 sha256 前 12 位`。两个账号 ID 哪怕净化后长得一模一样（比如 `a/b:c` 和 `a_b_c` 都会变成 `a_b_c`），哈希一定不同，绝不可能落到同一个文件上。

**第三层：读的时候再核对一次。** 打开文件后先看里面的 `userId` 跟当前登录账号是否一致。不一致（文件被手工改过、被覆盖错、迁移出问题）就**当成空记忆处理**，并在服务端日志打一行 `[agent-memory] 账号 xxx 的记忆文件里记的是 yyy，已按空记忆处理，避免串号。`。原则是：**宁可忘记，不可串号。**

另外：
- `/api/*` 在登录模式（`AUTH_MODE=server`）下有全站登录守卫，没登录直接 401，拿不到任何人的记忆；
- 账号 ID 用的是数据库主键（UUID），全库唯一。

## 4. 接口（前端只用这三个）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/student/agent/memory?limit=60` | 进页面时拉**当前登录账号**的记忆（取最近 N 句，最多 400） |
| POST | `/api/student/agent/memory` | 说一句就记一句，body：`{ role, content, page }` |
| DELETE | `/api/student/agent/memory` | 清空**当前登录账号**的全部记忆（面板右上角「清空」按钮调它） |

接口上**没有「查某个账号的记忆」这种入口**，谁调就只能拿到谁自己的——前端就算改代码也拿不到别人的。

服务器代码：`server/agent-memory-store.js`（只负责文件读写）；路由在 `server/index.js` 的 `/api/student/agent/*` 一段。

## 5. 为什么切页面不会丢

- 记忆不由页面组件保管。`StudentAgentDock.vue` 每次挂载都会 `GET /api/student/agent/memory` 把历史拉回来，说一句话就 `POST` 回去。
- 五页读的是同一个账号的同一份文件，所以绘画页说的话，视频页也看得到。
- 页面只保留「这次打开后的临时显示」，真正的数据在服务器文件里。

## 5.1 和记忆分开的另一件事：画布设置（`canvasContext`）

记忆解决的是「**你刚才说了什么**」；画布设置解决的是「**你手上正在画什么**」。两件事分开存：记忆落盘，画布设置**不落盘**，每次说话时现取现发。

不带这一份的话，学生说「耳朵改大一点」，老师不知道要改哪张画，只能另编一个新主题——这就是以前那个毛病。

### 发出去的样子

跟老师说话时，请求体里多一个 `canvasContext`：

```json
{
  "page": "paint",
  "text": "耳朵改大一点，再来一张",
  "history": [{ "role": "user", "content": "……" }],
  "canvasContext": {
    "prompt": "一只橘猫坐在窗台上看夕阳",
    "lastPrompt": "一只橘猫坐在窗台上看夕阳",
    "style": "水彩风格",
    "ratio": "16:9",
    "count": "2",
    "negativePrompt": "模糊，畸形",
    "theme": "IP形象",
    "quality": "高清",
    "doneCount": 4
  }
}
```

### 字段表

| 字段 | 含义 | 绘画 | 视频 | 3D | 课程 | 报告 |
|---|---|---|---|---|---|---|
| `prompt` | 画布上真正生效的那句描述 | 上一次生成用的描述 | 正向提示词 | 模型描述 | 课程简介 | 报告想法 |
| `lastPrompt` | 上一次提交的描述（输入框清空后仍留着） | ✓ | | ✓ | | |
| `style` | 已选风格 | ✓ | | | | |
| `ratio` | 画面比例 | ✓ | ✓ | | | |
| `count` | 这一轮要几张 | ✓ | ✓ | | | |
| `duration` / `music` | 时长、配乐 | | ✓ | | | |
| `edition` / `quality` | 版本、画质 | ✓（画质） | | ✓ | | |
| `negativePrompt` | 不想出现的元素 | ✓ | ✓ | | | |
| `theme` | 当前主题 / 课程名 / 报告名 | ✓ | | | ✓ | ✓ |
| `doneCount` | 这一轮已经画出几张 | ✓ | | | | |

### 三条硬规矩

1. **后端只认白名单**（`normalizeAgentCanvasContext`）。表里没有的字段一律丢掉，每项都截断，空值不占行；全空时返回 `null`，提示词一个字不加——旧行为不回归。
2. **绘画页不传输入框里的文字**。智能体模式下底部大框里是「学生对老师说的话」，当画布内容传回去会让老师自己跟自己绕圈。只传 `selectedVersion` 的提示词和 `lastSubmittedPrompt`。
3. **提示词里怎么用**。服务器把它拼成 `【学生画布上现在是这样】` 一段清单，并加第 7 条判断规则：

   > 学生说「改一下」「再大点」「重画」「颜色换掉」「再来一张」这类没有主体的指令时，指的就是画布上那张画。要在「画布上写的提示词 / 上次画出来的那句描述」的基础上改，保留原有的主体、风格和比例，只改学生点到的地方，不许另编一个全新主题。
   > 学生说的是全新主题就按新主题来，画布内容只当风格和比例的参考。
   > prompt 字段要写成「可以直接拿去出图的完整描述」，把画布上仍然有效的部分并进去。

## 6. 老数据会自动迁移

改成一账号一文件之前，用的是单个 `agent-memory.json`（所有账号挤在一个文件里）。如果那个文件里还有数据，第一次读取时会自动按账号拆成独立文件，老文件清空成空壳。拆分是「新文件已有内容就不覆盖」，只做一次，不会把新数据吞掉。

已经拆过的老文件可以直接删。现在这台机器上那个文件是空的，已经删掉了。

## 6.1 无限画布助手：存在浏览器，但按账号分开

`/student/canvas` 右侧那个「AI画布助手」是**另一个助手**，跟这一份不一样：

| | 五页 AI 老师（本文 1–5 节） | 无限画布助手（本节） |
|---|---|---|
| 存在哪 | 服务器文件 `agent-memory/` | 浏览器 localStorage |
| 记什么 | 完整聊天，跨设备可续 | 最近 10 条，只在本机这一台浏览器 |
| 为什么这样 | 学生作品上下文要跟着人走 | 画布本身就是服务端文档，对话只是「刷新后能接着看」的体验数据 |

**以前的问题**：键名写死成 `canvas-assistant-session-v1`，不分账号、退出也不清。A 学生用完退出、B 学生登录，B 打开助手就看见 A 的全部对话。

**现在的做法**（`src/utils/accountScope.js`）：键名后面拼账号指纹，`canvas-assistant-session-v1 :: <净化ID>-<hash>`。A 的键和 B 的键不是同一个键，谁都读不到谁的。同一份工具也用在：

- `ai-workflow-canvas-document-id` — 「上次打开哪张画布」
- `ai-workflow-canvas-stage1-v2` — 演示模式下存在本机的画布内容
- `ai-workflow-connection-guide-seen-v2` 这类单独的开合状态**没有**改用（它不含任何个人信息，且换了人还提示一遍反而更烦）

三条配套规矩：

1. **老的不分账号的键必须丢掉，不许继承**。里面那句话不知道是谁的，挪给当前登录的人等于送出去。进画布时 `discardLegacyStorageKey()` 直接删。
2. **拿不到账号时退成 `anonymous` 一份**，不报错、不乱指。本地 demo 模式本来只有一个人。
3. **hash 只是防撞，不是加密**。目标是「不串号」，不是「防本机的人翻 devtools」。真要防翻，得连对话一起搬到服务器，那是另一个改动。

## 7. 上架到服务器时要做什么

1. 把 `server/data/`（或 `AI_DATA_DIR` 指向的目录）挂成服务端的持久化目录，不要跟着代码发布被覆盖。
2. 备份策略里加上 `agent-memory/` 这个目录。
3. 现在这个实现是单机文件读写。以后学生量大了要换成 PostgreSQL，只需要替换 `server/agent-memory-store.js` 里的读写实现，接口和前端都不用动。

## 8. 已知限制

- **同一个账号开两个标签页不会实时同步**：A 标签页说的话，B 标签页要刷新才看到。
- 未登录（本地 demo 模式、没登录）时记到一个固定的 `demo-student` 名下；这种模式下本来就只有一个人在用，不会串到真实账号。
- 一个账号文件最多 400 句 / 最坏 2.36 MB（400 句 × 2000 字）。正常聊天（100 句 × 80 字）约 42 KB。

## 9. 怎么验收

```bash
# 账号隔离（三层保险逐条打）
node scripts/verify-agent-memory-isolation.mjs

# 记忆本身（跨页面、刷新、清空）
node scripts/verify-agent-memory.mjs

# 画布设置（前端发出的请求体 + 后端拼出的提示词）
node scripts/verify-agent-canvas-context.mjs

# 无限画布助手：同一浏览器换账号读不到上一个人的对话
node scripts/verify-canvas-assistant-isolation.mjs
```

四个脚本都零花费（`/understand`、`/api/ai/canvas/assistant` 用假回包，不调用真实模型、不出图），需要 `scripts/dev.mjs` 已经跑起来。

- 隔离脚本 **30 项**：A 写 A 读、B 读到 0、B 写不污染 A、磁盘两个文件、长得像的 ID 不撞车、文件被改成别人时读空、清空只清自己、空内容拒收、老数据迁移不丢、运维列表不含正文；再加两个真实浏览器（`ceshi2` / `ceshi3`）互相看不到、清一个另一个不受影响。
- 记忆脚本 **11 项**：起点干净 → 说一句 → 落盘 → 刷新还在 → 切页面还在 → 清空归零。
- 画布设置脚本 **18 项**：真实浏览器点进智能体模式说话，抓 `/understand` 的请求体（8 项，含「画布提示词不能等于学生刚说的那句」这条防回声断言）；再把 `server/index.js` 里的真实函数抠出来单跑（10 项：白名单丢字段、空快照返回 null、六类信息都进了提示词段）。
- 画布助手隔离脚本 **34 项**：存储层 16 项（两个账号两个键、净化后同形 ID 不撞、写读互不可见、坏 JSON 自愈、清只清自己、老键被丢弃不继承）；真实浏览器 18 项（`ceshi2` 说话 → 刷新还在 → 退出换 `ceshi3` 看不到 → 乙说完甲的话还在甲键里 → 换回甲仍看得到自己的、看不到乙的）。
