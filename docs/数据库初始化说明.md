# 数据库初始化说明

## 适用范围

本文用于正式开发、测试和服务器部署。正式环境必须使用 PostgreSQL 和 `AUTH_MODE=server`，不得使用前端 Mock 登录或浏览器全局业务数据作为正式数据来源。

## 初始化步骤

1. 安装 PostgreSQL 15 或更高版本，并创建空数据库，例如 `ai_art_studio`。
2. 将 [server/.env.example](/D:/ruanjian/Codex/AIhuihua/New%20project%204/project-005-AI创意美术教学平台MVP/server/.env.example) 复制为 `server/.env`，填写 `DATABASE_URL`、正式域名和强密码。开发环境使用 HTTP 时把 `SESSION_COOKIE_SECURE` 临时改为 `false`；正式 HTTPS 环境必须为 `true`。
3. 执行 `pnpm db:migrate`，建立机构、校区、账号、关系、会话、审计和私有文档表。
4. 执行 `pnpm db:bootstrap-admin`，仅创建第一个管理员账号；账号已经存在时不会覆盖密码。
5. 把前端环境变量 `VITE_AUTH_MODE` 设为 `server`；可设置 `VITE_ORGANIZATION_CODE` 预填机构代码。启动服务后使用管理员账号登录。
6. 确认 `AI_DATA_DIR` 指向服务器可备份的持久化目录，并将数据库和该目录一起纳入备份策略。

## 验收检查

- `GET /api/health` 返回 `authMode: "server"` 和 `databaseConfigured: true`。
- 未登录请求任意业务 `/api` 地址返回 401。
- 登录成功后浏览器中只有 HttpOnly 会话 Cookie，不出现 Mock Token。
- A 账号不能通过 `GET/PATCH/DELETE /api/me/documents/:id` 访问 B 账号的文档 ID。
- 退出后再次登录，服务端已保存的文档仍能读取。
