## 一、结论先说（你只需要看这 5 条）

1. **现在课程确实 100% 存在浏览器里**，换电脑、换浏览器、清缓存 = 课程全没了。这不是"以后再说"的问题，是**上线阻断项**。
2. 修复方案**不需要新建数据库**，也不需要重写课程管理页面。项目里已经有一张建好却一直没用过的表 `organization_documents`，正好是"机构级课程库"的位置；课程授权照抄已经在跑的 `ai_skill_assignments`（AI 玩法授权）那套四级权限模型即可。
3. 课程封面/视频/PPT 目前也是双份状态：一份在浏览器 IndexedDB，一份在服务器但**没登录校验、没有归属**。这次一并改成"服务器唯一来源 + 登录鉴权 + Range 支持"。
4. 这门课和"甲方智能体对话"是**同一批数据的两面**：对话要知道"这节课视频讲了什么、题目是什么、学生答对没有"，这些都得先上服务端。所以**建议合并成一次改造**，只做对话不改课程库，做完还是要返工。
5. 全部做完预计 **9～13 个工作日**（单人），分 4 个阶段，每阶段可独立验收、独立回退。

## 二、现状盘点（已逐文件核实，不是猜的）

### 2.1 课程主数据：纯 localStorage

`src/stores/courseStore.js`（284 行）

| 项目 | 现状 |
|---|---|
| 存储位置 | `localStorage['art-studio-courses']`，一个 JSON 数组 |
| 写入 | `persist()` 里只有 `localStorage.setItem(...)`，**全文没有一处 `apiClient`** |
| 初始数据 | 未登录过也会显示 3 门硬编码示例课（`seedCourses`） |
| 学生可见性 | `authorizedCourses` getter 用**写死的** `currentStudent='小画家阿橙'`、`currentClass='AI创意美术A班'` 过滤，**完全没接登录账号** |
| 调用方 | `CourseCenter.vue`、`TeacherWorkbench.vue`、`AdminDashboard.vue`、`ProfileCenter.vue`、`H5ReportGenerate.vue` |

**后果**：换设备看不到自己传的课；A 老师传的课 B 老师也能看到（同一个浏览器）；学生端"谁能学哪门课"是假的。

### 2.2 课程素材：IndexedDB 与服务器双份，且服务器那份是裸的

| 素材 | 浏览器 | 服务器 | 问题 |
|---|---|---|---|
| 封面 | ✅ IndexedDB | ❌ **完全没上传** | 换设备封面全丢 |
| 视频 | ✅ IndexedDB | ⚠️ 有上传，但失败只 `console.info` **静默降级** | 换设备视频消失且用户无感知 |
| PPT/PDF | ✅ IndexedDB | ✅ 落盘 `server/data/course-ppt-assets/` | 可读但无鉴权 |

素材读取接口 `GET /api/course-video-assets/*`、`/api/course-ppt-assets/*`：
- 目录名 `video-{时间戳}-{随机6位}`，**没有机构、没有归属人**
- **不做登录校验**（知 URL 即可下载）
- 上传接口 `POST /api/course-video/upload` 用 base64 塞进 JSON body，且 `readJson(req)` **没传 maxBytes**（默认 0 = 不限），一个 500MB 视频会把服务端内存打满

### 2.3 服务端完全没有课程接口

全项目 `grep` 结果：**不存在** `/api/courses`、`/api/admin/courses`、`courses` 表。

`server/schema.sql` 里有 `organization_documents`（第 202 行）：

```sql
CREATE TABLE IF NOT EXISTS organization_documents (
  id TEXT PRIMARY KEY,
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  campus_id TEXT REFERENCES campuses(id),
  document_type TEXT NOT NULL,
  resource_key TEXT NOT NULL,
  data JSONB NOT NULL DEFAULT '{}'::jsonb,

```

**这张表建好了，却一行读写代码都没有，也没有 RLS。** 这就是现成的课程库落点。

### 2.4 为什么不能用 `user_documents` 存课程

`user_documents` 开启了 `FORCE ROW LEVEL SECURITY`，其中：

```sql
CREATE POLICY user_documents_insert_policy ... WITH CHECK (
  owner_user_id = current_setting('app.user_id', true)
  AND current_setting('app.user_role', true) = 'student'   -- ← 硬约束
);
```

**只有学生能写**。老师和管理员写不进去。所以课程主数据**必须**走 `organization_documents`（或新表），不能复用学生文档表。

### 2.5 课程授权模型与数据库完全脱节

现状：课程上存的是 `authorizedClasses: ['AI创意美术A班']`、`authorizedStudents: ['小画家阿橙']` —— **纯字符串数组**，靠名字匹配。

数据库里真实存在的是：`school_classes`（班级）、`class_students`（学生-班级关系）、`permission_group_members`（权限组成员）。两边**没有任何关联**。

教师端"授权班级/学生"的选项还是写死的常量：
```js
const classOptions = ['AI创意美术A班', ...]
const studentOptions = ['小画家阿橙', '晨晨', ...]
```

### 2.6 课程分类也在 localStorage

`AdminDashboard.vue`：`adminCourseCategoryStorageKey = 'art-studio-course-categories'`，自定义分类只存浏览器。

### 2.7 智能体记忆存在"串场"隐患

`server/agent-memory-store.js`：**一个账号一个文件，五个页面（绘画/视频/3D/课程/报告）共用一份**，`listAgentMessages` 读取时**不按 page 过滤**。

所以：学生在"AI 绘画"页跟老师聊的内容，切到"课程"页时智能体也"记得"。本次改造必须**按课程隔离**，否则 A 课的甲方会说出 B 课的题目。

## 四、数据库设计（4 处改动，全部幂等可重复执行）

### 4.1 改造 `organization_documents` 承载课程

只加两列 + 一个唯一索引，**不动已有数据**：

```sql
ALTER TABLE organization_documents ADD COLUMN IF NOT EXISTS title TEXT NOT NULL DEFAULT '';
ALTER TABLE organization_documents ADD COLUMN IF NOT EXISTS version INTEGER NOT NULL DEFAULT 1 CHECK (version > 0);

-- 同一机构下「课程 + 课程ID」唯一，防止重复写入
CREATE UNIQUE INDEX IF NOT EXISTS idx_org_documents_type_key_unique
  ON organization_documents (organization_id, document_type, resource_key)
  WHERE deleted_at IS NULL;
```

- `document_type = 'course'`
- `resource_key = course.id`
- `data` = 课程全量 JSON（字段与现在 `courseStore` 里的完全一致，前端零改造就能读）
- `version` 用于乐观锁：老师 A 和老师 B 同时改同一门课，后提交的会收到冲突提示，不会互相覆盖（`user_documents` 已有这套机制，照搬）

**为什么用 JSONB 而不是给每个字段建列**：课程字段会继续长（这次就要加 `agentPersona`、`dialogConfig` 等）。JSONB 免去每加一个字段就跑一次 DDL，而课程唯一的"需要按列查"的地方是授权，授权已经单独建表了。

### 4.2 新建 `course_assignments`（课程授权）

直接照抄 `ai_skill_assignments` 的四级模型（organization / campus / class / permission_group），这套已经在生产跑，风险和心智成本最低：

```sql
CREATE TABLE IF NOT EXISTS course_assignments (
  id TEXT PRIMARY KEY,
  course_id TEXT NOT NULL,              -- 对应 organization_documents.resource_key
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  campus_id TEXT REFERENCES campuses(id),
  class_id TEXT REFERENCES school_classes(id),
  permission_group_id TEXT REFERENCES permission_groups(id),
  scope_type TEXT NOT NULL CHECK (scope_type IN ('organization','campus','class','permission_group')),
  status TEXT NOT NULL DEFAULT 'enabled' CHECK (status IN ('enabled','disabled')),
  created_by_user_id TEXT REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (
    (scope_type='organization' AND campus_id IS NULL AND class_id IS NULL AND permission_group_id IS NULL)
    OR (scope_type='campus' AND campus_id IS NOT NULL AND class_id IS NULL AND permission_group_id IS NULL)
    OR (scope_type='class' AND class_id IS NOT NULL AND permission_group_id IS NULL)
    OR (scope_type='permission_group' AND permission_group_id IS NOT NULL AND class_id IS NULL)
  )
);
CREATE INDEX IF NOT EXISTS idx_course_assignments_course ON course_assignments(course_id, organization_id) WHERE status='enabled';
```

学生可见性判断 SQL（照抄 `server/ai-skill-store.js:519` 的 `studentVisibleSql`）：

```sql
EXISTS (
  SELECT 1 FROM course_assignments a
  WHERE a.course_id = d.resource_key AND a.organization_id = $org AND a.status='enabled' AND (
       a.scope_type='organization'
    OR (a.scope_type='campus' AND a.campus_id = $campus)
    OR (a.scope_type='class' AND EXISTS (
         SELECT 1 FROM class_students cs
         WHERE cs.class_id=a.class_id AND cs.student_user_id=$uid AND cs.organization_id=$org))
    OR (a.scope_type='permission_group' AND EXISTS (
         SELECT 1 FROM permission_group_members pgm
         WHERE pgm.group_id=a.permission_group_id AND pgm.user_id=$uid AND pgm.organization_id=$org))
  )
)
```

**迁移映射**：老的 `authorizedClasses: ['AI创意美术A班']` → 迁移时按**班级名**去 `school_classes` 里匹配，命中就生成一条 `scope_type='class'`；匹配不到（比如那个班在数据库里不存在）就**记为未授权并在迁移报告里列出来**，交给管理员重新授权。老 `authorizedStudents` 同理，但学生名可能重名 —— 迁移脚本会**只匹配唯一命中**，重名一律进待确认清单，绝不猜。

### 4.3 新建 `course_assets`（素材登记）

```sql
CREATE TABLE IF NOT EXISTS course_assets (
  id TEXT PRIMARY KEY,
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  campus_id TEXT REFERENCES campuses(id),
  owner_user_id TEXT NOT NULL REFERENCES users(id),
  asset_kind TEXT NOT NULL,             -- cover | video | ppt | pdf
  original_name TEXT NOT NULL DEFAULT '',
  mime_type TEXT NOT NULL,
  storage_key TEXT NOT NULL UNIQUE,     -- course-assets/{orgId}/{随机}-{hash}.mp4
  byte_size BIGINT NOT NULL CHECK (byte_size >= 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);
CREATE INDEX IF NOT EXISTS idx_course_assets_org_kind
  ON course_assets(organization_id, asset_kind, created_at DESC) WHERE deleted_at IS NULL;
```

**不开 RLS**，理由：这张表只有服务端代码读写，权限判定在路由层（谁能看这门课 → 才能读它的素材）。开 RLS 反而需要给老师/管理员写策略，绕一圈没收益。

### 4.4 新建 `org_course_categories`（课程分类服务端化）

```sql
CREATE TABLE IF NOT EXISTS org_course_categories (
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  id TEXT NOT NULL,
  label TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','archived')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (organization_id, id)
);
```

7 个内置分类（LOGO设计/门头设计/服装设计/产品设计/IP形象/动漫人物/综合项目）作为种子数据在每个机构首次访问时自动写入。

### 4.5 对话记忆：不建新表

直接复用 `user_documents`（RLS 已允许学生写）：

| 用途 | document_type | resource_key | data |
|---|---|---|---|
| 学习进度 | `course-learning` | `course.id` | 现有 4 步状态 |
| **对话记录** | `course-dialog` | `course.id` | `{ stage, rounds, persona, messages: [...] }` |

**按课程隔离是天然的**：唯一索引 `(organization_id, owner_user_id, document_type, resource_key)` 保证了"一个学生 + 一门课"只有一条对话记录。
切换课程 = 换 `resource_key` = 换一条完全独立的记录，**不可能串场**。

现有的 `agent-memory-store.js`（账号级、五页共用）**完全不动**，继续服务其他四个页面。

## 六、权限规则（三层，逐条明确）

### 6.1 谁能写课程

- **管理员**：本机构全部课程（走 `/api/admin/` 前缀 + `requireRole(['admin'])`）
- **教师**：自己创建的课程 + 所在权限组被授权 `courseUpload` 权限的课程
- 权限点复用现有的 `accountPermissionStore`（已服务端化）：`courseLibraryView`（看课程库）/ `courseUse`（用课教学）/ `courseDistribute`（发放给学生）/ `courseUpload`（上传新课程）

### 6.2 学生能看到哪门课

必须是**已发布（`status='published'`）+ 有 `course_assignments` 记录 + 命中四级范围之一**。三个条件同时成立，缺一不可。

这条规则彻底替换现在的"名字字符串匹配"。

### 6.3 谁能读素材

能读到这门课 → 才能读它的视频/PPT/封面。服务端拿 `assetId` 反查 `course_assets`，再查该课程是否对当前用户可见。**直接暴露一个可猜的 URL 就能下载素材的日子结束了。**

## 八、对话记忆隔离 & 防跑题

### 8.1 记忆隔离（三重保证）

1. **存储层隔离**：`user_documents` 唯一索引 `(org, owner, document_type, resource_key)` → 一个学生、一门课、一条记录
2. **读取层过滤**：`GET /api/student/course-dialog/:courseId` 强制按 `resource_key = courseId` 查，不接受前端传任意 key
3. **上下文层隔离**：拼 prompt 时只注入**当前课程**的视频文本、题目、学生已答内容；`agent-memory-store.js` 那份账号级记忆**不注入课程对话**

### 8.2 防跑题（四道锁）

| 锁 | 机制 |
|---|---|
| **阶段锁** | 服务端维护 `stage: 'intro' → 'quiz' → 'dialog' → 'wrapup' → 'done'`，每个阶段只接受对应操作。学生没答题就说"我想聊别的"，服务端直接回"我们先把这道题选完"，`stage` 不推进 |
| **话题边界** | prompt 里注入"你只能讨论本课程内容（{课程标题}），学生问到无关话题时，用一句话把他拉回任务"。同时服务端做关键词兜底：完全无关的输入直接走 `action.clarify`，不消耗大模型调用 |
| **角色不破** | 系统提示里锁死"你是{甲方/老师}，不是 AI 助手，不说'我是语言模型'，不给课外知识"。学生要求"你当我的英语老师"→ 服务端识别到角色切换请求，回固定话术 |
| **轮次硬上限** | `dialogConfig.maxRounds`（默认 8，后台可配），存服务端。到上限后阶段强制推进到 `wrapup`，**服务端拒绝继续对话** |

**必须说清楚的做不到的事**：内容安全过滤（脏话、暴力、涉政）目前项目**没有这个能力**。方案里能做到的只有关键词黑名单兜底 + 越界话题拉回。真正的语义级内容审核需要接第三方审核 API（阿里云内容安全 / 腾讯云天御），那是独立的一笔工作量和费用，**不在本次范围**，需要你单独决定。

### 8.3 结束条件（已确认修正）

不是"聊满 8 轮结束"，而是**"甲方要的信息问齐了就结束"**——这些信息就是课程 `designRequirements` 的 5 项（尺寸规格 / 必备元素 / 形象来源 / 风格要求 / 使用场景）。

服务端维护"已问齐几项"，全齐 → `wrapup`。8 轮只是**保险丝**，防止学生一直绕圈子不结束。

## 九、数据迁移方案

### 9.1 存量数据在用户浏览器里，服务端拿不到

这是本次迁移最现实的问题：**老师的课程在他自己电脑的浏览器里，服务器无法主动去读**。

所以迁移只有一条路：**前端主动上传**。

### 9.2 迁移步骤（三选一，建议选 A）

**方案 A（推荐）：首次登录自动提示导入**

1. `courseStore.hydrateFromServer()` 完成后，检查 `localStorage['art-studio-courses']` 是否存在
2. 存在 → 顶部弹一条：`检测到本机有 N 门本地课程，是否导入到服务器？[导入] [稍后] [不再提示]`
3. 导入流程：逐门 `POST /api/courses`，把 IndexedDB 里的封面/视频/PPT 一并 `POST /api/course-assets` 上传
4. 每门课单独报告成功/失败，**失败的不删除本地数据**，允许重试
5. 全部成功后，本地 key 改名为 `art-studio-courses-migrated-backup`（**不删，留退路**）

**方案 B：后台提供"导入本地课程"按钮**，手动触发，逻辑同上。

**方案 C：不管，重新建课。** 只适合课程数量很少的情况。

### 9.3 授权迁移

`authorizedClasses` 字符串 → 按名字匹配 `school_classes`：
- 唯一命中 → 生成 `course_assignments(scope_type='class')`
- 未命中或重名 → 进"待确认授权"清单，管理后台可见，手动补
- **绝不猜测**，宁可漏授权也不给错人

### 9.4 迁移脚本形态

`scripts/migrations/2026xx-course-server.sql`（表结构）+ `scripts/migrate-course-data.mjs`（一次性数据迁移，从 `server/data` 里能读到的部分，比如历史视频/PPT 的机构归属推断）。

写入 `scripts/migrate-db.mjs` 的执行序列，幂等可重复跑。

## 十四、需要你拍板的 3 件事

### 决定 1：人设自动判断 + 后台手动覆盖，接受吗？

**建议方案**：`agentPersona: 'auto'|'client'|'teacher'`，auto 时按课程类型映射（商业委托类→甲方，创作技法类→老师），后台可强制覆盖。若映射错，老师改一下下拉即可，不用改代码。

**需要你确认**：这个映射规则你认可吗？还是希望**所有课程统一甲方**（更简单，也不用管映射错的情况）？

### 决定 2：完成标准改成"答题 + 至少聊 2 轮"，接受吗？

**背景**：现在进度第 2 步是"所有题目都答了"，第 3 步是"保存了创意"。改成对话模式后，"保存创意"这一动作会变成对话的收尾环节。

**建议方案**：
- 第 2 步（随堂练习 25%）：**所有选择题答完**
- 第 3 步（创意记录 25%）：**创意内容非空 + 至少完成 2 轮对话**

**需要你确认**：这个标准可以吗？还是希望更宽松（只答题就够）／更严格（必须甲方问齐所有需求项才给分）？

### 决定 3：课程上服务端 与 智能体对话，合并成一次改造还是分两批？

**建议方案**：**合并**。理由：对话需要读"课程视频文本、题目、学生答案"，这些数据必须先上服务端；先做对话就等于建在沙子上，做完还要返工。

**代价**：一次性改动面较大（约 10～13 天），中间不能上线。

**分两批的好处**：阶段 1+2 完成（5～6 天）就可以先上线一版"数据不丢"的稳定版本，对话作为第二批。风险更小，但总工期会多 1～2 天（重复验收）。

**需要你确认**：你更看重"一次做完"还是"先上线稳定的"？
