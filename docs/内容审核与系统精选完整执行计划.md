# 内容审核与系统精选完整执行计划

日期：2026-10-16  
状态：开发与隔离验收已完成（2026-10-16）。用户确认本次不进行付费 AI 调用，学校已有授权由管理员登记。真实 AI 看图、计费和线上启用待另行验收。实施结果见[内容审核实施与验收说明](内容审核实施与验收说明.md)。  
设计依据：用户认可的[内容审核面板效果图](方案图/内容审核面板效果图-v1.png)。图中的统计数量、85 分、100 件/天及开关状态均为示例，不作为已有能力或默认启用依据。

## 1. 本次要实现的结果

在现有后台“内容审核”中完成可配置的 AI 审核、自动精选、自动上架和人工处理闭环。管理员可以修改开关、选择模型、填写审核要求和优秀作品标准；保存后由服务端执行，并能查看判断理由、失败原因和操作记录。

作品有两个入口，共用同一套审核、记录和发布机制：

| 入口 | 触发方式 | 上架条件 |
|---|---|---|
| 学生主动投稿 | 学生提交自己的最终绘画作品 | 安全检查通过且内容完整；自动上架开启时直接发布，否则转人工确认 |
| 系统自动精选 | 已授权参与的最终绘画作品保存成功后，服务端自动发现 | 安全检查通过、满足优秀标准和去重要求；自动上架开启时发布，否则转人工确认 |

自动精选未入选不等于违规，也不影响作品保存在个人作品集或之后主动投稿。管理员保留复核、驳回、下架和有理由的人工纠错能力。

第一期范围：现有绘画项目的最终图片、标题和创作说明；后台、作品集、工作台投稿入口、作品广场，以及必要的数据与图片访问链路。

本期不包含：视频/3D/H5 报告审核、无限画布整份文档自动公开、历史作品全库扫描、新增匿名互联网广场、自动点赞与排行榜、重新建设置顶系统。保留这些模块的现有功能。历史作品可继续主动投稿，批量补审另行确定数量和费用。

## 3. 面板及每个选项的实际行为

### 3.1 页面结构

- 保留深色侧栏、橙色操作按钮和原后台入口。
- 页内设置“规则设置”“审核队列”“审核记录”三个视图，复用同一份状态和接口。
- 规则设置左右分别为“AI 内容审核”“系统自动精选”，下方为“发布策略”；保留队列概览及进入完整列表的入口。
- 顶部统计使用本机构真实数据。请求失败显示失败和重试入口，不能以数字 0 代替加载失败。
- 操作提供“恢复默认”“选择作品试审”“保存并启用”；试审有调用提示，不发布作品。
- 窄屏改为上下排列，表格适配为可读卡片或局部滚动，操作按钮不能遮挡内容。

### 3.2 配置表

| 配置项 | 行为与校验 | 初次迁移策略 |
|---|---|---|
| AI 自动审核 | 开启后对新任务执行图片与文字审核；关闭后手动投稿进入人工队列，自动精选暂停 | 新 AI 能力不因旧开关为真而自动启用 |
| 审核模型 | 从现有 API 配置选择已启用的视觉候选模型进行试审；正式自动运行要求视觉验证通过，禁用模型立即停止新调用 | 不擅自选择供应商，不重复配置密钥 |
| 启用自定义审核要求 | 开启时将输入要求用于审核；关闭时保留文字，使用平台基础审核标准 | 关闭；预填示例可编辑 |
| 自定义审核要求 | 限长 2,000 字；开启但内容为空时阻止保存并提示 | 不发送未保存的文字给正式任务 |
| 增强个人信息检查 | 对姓名、联系方式、二维码等增加检查说明；关闭不取消平台基础隐私保护 | 建议开启；文案比效果图进一步明确作用 |
| 相似作品检查 | 在精确重复拦截基础上增加近似图片检查；疑似重复转人工，不直接认定侵权 | 建议关闭，验证误判情况后启用 |
| 系统自动精选 | 针对生效时间之后保存的、符合授权与最终作品条件的图片触发 | 关闭，管理员明确保存启用后运行 |
| 启用自定义优秀作品标准 | 开启使用输入要求；关闭后使用平台默认精选标准，保留原文字 | 关闭；默认标准明确展示 |
| 自定义优秀作品标准 | 限长 2,000 字；要求 AI 给出评分依据，不只是分数 | 允许管理员编辑后试审 |
| 优秀评分门槛 | 0–100 整数，只决定系统精选，不以此阻止正常主动投稿 | 建议试运行 85 分，属于待校准值 |
| 每日审核数量上限 | 正整数；建议配置范围 1–1,000，并受平台总预算约束 | 效果图 100 仅为示例；上线额度另确认 |
| 审核通过自动上架 | 只发布满足条件的审核快照；关闭时留待人工确认 | 关闭 |
| 审核异常处理 | 超时、空结果、结构错误、无视觉能力及供应商失败均不自动发布 | 固定转待复核，不能配置成“失败视为通过” |
| 生效范围 | 配置版本只分配给保存后创建的新任务 | 不追溯调用历史作品 |

依赖关系必须可见：AI 关闭、模型未验证、凭据失效或预算未配置时，自动精选显示暂停原因。允许保存未启用的设置，但不允许界面显示“已运行”而服务端静默跳过。

### 3.3 保存、试审和默认值

1. 编辑时修改的是草稿，所有选项经“保存并启用”统一提交，服务端校验成功后才更新生效版本。
2. 保存失败保留输入；有未保存修改时提供离开提示。并发编辑通过版本号检测冲突，避免后保存者覆盖其他管理员修改。
3. “恢复默认”只恢复当前表单草稿，仍需保存；不重置投稿和审核记录。
4. “选择作品试审”使用当前草稿规则，明确显示“未保存规则的试审结果”；只能选择管理员权限范围内、允许用于该用途的作品或专用测试图。
5. 试审返回安全结论、精选评分、原因、模型与规则版本，计入调用额度；不写入广场发布状态，不触发自动精选，也不保存为正式规则。
6. 设置关闭审核/自动发布等限制时，正在执行的任务提交结果前必须重新检查限制；不能凭旧规则在关闭后继续上架。其他普通规则变更由新任务使用新版本。

## 4. 审核、精选与发布的规则

### 4.1 处理顺序

授权与归属检查 → 最终图片完整性检查 → 精确重复与可选近似检查 → AI 图片/文字审核与评价 → 服务端校验结果 → 按来源及发布设置决定后续状态。

AI 只提供结构化建议，不能直接修改数据库、开关、权限或公开状态。标题、图片中的文字和学生创作说明均作为待审核内容，不能作为模型必须执行的指令。管理员自定义要求也不能覆盖平台基础安全与权限规则。

### 4.2 结果决策表

| 场景 | 学生主动投稿 | 系统自动精选 |
|---|---|---|
| 安全通过、内容完整，自动上架开启 | 上架审核通过的版本 | 达到精选门槛且无重复疑点才上架 |
| 安全通过，自动上架关闭 | 待人工确认 | 达到门槛后待人工确认 |
| 安全通过但低于精选门槛 | 不受精选门槛影响 | 标记“未入选”，不公开，不作违规驳回 |
| AI 判定可疑、理由矛盾或结果不完整 | 待人工复核 | 待人工复核 |
| AI 明确判定违规 | 驳回并提供可理解原因 | 不上架，记录原因 |
| 无凭据、额度耗尽、外部服务失败 | 显示具体原因，可转人工 | 暂停或待处理，不能自动上架 |
| 学生撤回、管理员下架、原作品删除 | 立即禁止发布与继续展示 | 自动任务不能重新发布 |

额度耗尽使用“等待额度”状态；外部失败使用“审核异常/待人工复核”。不把等待、未入选和违规混成一种“审核失败”。

### 4.3 优秀标准及人工纠错

- 平台默认评价考虑创意表达、主题契合、画面完成度与年龄适宜性，输出各维度理由和总分。
- 自定义标准作为评价依据，不能仅根据提示词长短或模型自称“优秀”决定上架。
- AI 评分是辅助筛选结果，不作为学生成绩或原创性证明；不对学生公开排名。
- 管理员可复核与纠错；纠正 AI 结论时必须记录人工理由，保留原 AI 结果，不伪造“AI 已通过”。
- 人工发布同样校验授权、图片可用、作品未删除及发布快照完整性。最终决定与 AI、人工原始记录分开保存。
- 管理员主动下架、学生主动撤回是持续有效的阻止标记。普通保存、重复投稿、后台重启、定时任务都不能清除；恢复需要明确操作并重新核验。

## 5. 授权、角色和公开内容

1. 复用“允许系统自动精选最终作品”入口，将状态、授权人、时间、说明版本保存到服务端；历史本地开关不自动迁移为同意。
2. 主动投稿需有清楚的公开说明。自动精选不要求每次投稿，但必须具备一次明确的参与和公开授权；授权说明包括必要图片和文字会交给所选供应商用于审核的用途及范围。
3. 未成年人授权采用现有监护人关联关系或学校已确认的授权流程，具体方式列入执行前确认项。在未形成有效授权记录前，作品不进入自动精选。
4. 关闭“参与自动精选”停止新增自动任务；另提供“撤下已精选作品”选项，避免用户误以为关开关就一定删除已发布记录。撤回单件作品必须立即生效。
5. 公开内容白名单：审核过的展示图片、作品标题、平台昵称、课程/年龄段等必要信息。草稿、原始文档、手机号、学号、真实姓名、私有提示词、内部审核记录不随接口公开。
6. 公布固定版本快照。原作品修改后，旧发布版本继续保持不变；新版本重新审核通过后才能替换。删除原作品、撤回授权或下架时，列表与展示图片接口同步停止提供内容。
7. 沿用现有平台内登录访问范围，不在本期新增匿名访问。当前公开查询可汇总已发布作品；机构间只能看到允许公开的快照，不能因上架读取别人的原始文档或私有资产。
8. 管理员配置、队列、试审和人工操作都限制在其机构及已有管理范围内。学生仅能提交、查看状态及撤回自己的作品；教师、家长不能借学生接口替人投稿或修改审核规则。

## 6. 服务端任务、AI 接口和费用

### 6.1 持续执行机制

- 使用 PostgreSQL 保存待审核任务，服务端后台处理；首期不增加 Redis 等独立运行依赖。
- 最终作品保存与“待处理事件”在同一数据库事务内落地，AI 调用在保存成功后异步执行；模型慢或失败不阻塞学生创作保存。
- 仅处理实际支持的绘画文档和真实最终图片。普通自动保存、无关字段修改、视频/报告保存不得触发审核。
- 任务标识包含机构、文档、最终版本、审核内容指纹和规则版本。主动投稿与自动精选合并同一版本的审核任务，记录来源与不同发布条件，避免重复扣费或重复上架。
- 内容指纹包含图片、标题、会影响审核的说明及年龄/课程上下文；不能只按图片缓存而漏审后来修改的标题。
- 审核结果复用限定于同一机构、同一权限范围及相同模型/规则版本，不能跨机构用私有作品结果做缓存或展示。
- 使用数据库锁和处理租约领取任务；进程重启可恢复，多个服务实例不能重复领取同一任务。
- 已发给供应商但结果不明的任务不能因租约到期立即重复付费调用；标记待确认，支持管理员重试并记录可能重复计费。
- 发布前再次核对任务版本、当前最终图片、授权、下架标记、删除状态和自动发布开关，防止旧结果覆盖新作品。

### 6.2 AI 接入

- 复用现有 API 配置、凭据读取与模型启停机制；新增审核用途的适配，不另建密钥管理。
- 必须发送经过权限校验的真实图片内容，不能把受保护的本地图片地址当作供应商一定可读的图片。
- 使用当前审核对象的授权上下文取图，限制图片大小、解码像素及来源；必要时按比例缩图，移除非必要元数据。小字无法识别时转人工，不能按未发现个人信息处理。
- 图片超过限制或无法读取时给出明确结果；尺寸与大小上限根据选定模型实际要求确定并记录，不能吞掉错误继续只审文字。
- 返回结构至少包含安全结论、风险分类、原因、质量维度、总分、精选建议。服务端校验枚举、长度、0–100 分数及字段完整性；不能解析的结果转人工。
- 明确指定本次模型与供应商，不沿用通用文本调用中遍历多个模型的隐式降级，以免重复收费或退到不支持看图的模型。
- 记录模型、规则版本、内容指纹、时间及用量。界面展示经过处理的解释，不展示密钥、完整上游诊断或私有内容。

### 6.3 调用控制

| 项目 | 首期建议 |
|---|---|
| 后台并发 | 1；压测和费用确认后再调整 |
| 单次请求超时 | 30 秒起，结合供应商能力校准 |
| 自动重试 | 最多 1 次，只针对可判断的临时失败；结果不明、鉴权失败、余额不足、格式不兼容不循环重试 |
| 每日统计 | 按机构、北京时间自然日统计，涵盖试审、主动投稿、系统精选和重试 |
| 数量与金额 | 任务数上限、实际请求次数、平台总预算分别控制；数量上限不等于金额预算 |
| 金额估算 | 按供应商实际价格及图片/输出上限预留额度；无法可靠计价时只开放已确认次数的试审，暂不启用无人值守调用 |
| 超额处理 | 原子预留额度，达到限制停止新调用，显示“等待额度/预算不足” |
| 调用测试 | 优先本地可控上游验证异常；真实测试只做经确认的少量调用 |

不默认扫描历史库，不做循环付费压力测试。现有付费绘画、视频、3D 等回归以隔离可控接口验证为主，避免为测试审核而重复生成作品。

| 原 `gallery_audit_settings` | AI 与模型选项、两个自定义要求及开关、精选门槛、限额、发布策略、配置版本与生效时间 |
| 原 `gallery_submissions` | 来源、审核对象版本、AI 结果、人工决定、精选结果、最终发布状态、快照引用、撤回/下架阻止标记 |
| 新的审核任务记录 | 领取状态、重试次数、租约、内容指纹、规则快照、用量及错误；任务历史与发布记录关联 |
| 新的授权记录 | 用户及机构、授权主体、授权范围、说明版本、授予与撤回时间 |
| 发布快照/资产记录 | 已审核的图片与公开元数据、版本关联及访问状态，不复制整份私有作品文档 |
| 原 `audit_logs` | 设置修改、试审、模型决定、人工纠错、发布、下架、撤回；系统动作明确标记来源，不冒用管理员账号 |

审核任务单独建表是因为现有 `ai_tasks` 只允许绘画、视频、3D、报告，并要求供应商任务编号；不能把内部审核硬塞成绘画任务。这里只增加同一审核模块所需的执行记录，不复制投稿或发布系统。

保留原接口字段，通过兼容映射统一状态；新增最终状态不以“人工通过”冒充 AI 自动发布。审核、精选、任务执行和发布状态分别记录，避免一个字符串承担所有含义。

### 7.2 迁移步骤

1. 在实施分支核对当前未提交修改并记录执行基线；不覆盖他人修改，不自动提交或拉取覆盖本地内容。
2. 备份目标数据库及相关持久化资产，写明恢复命令与备份位置；备份和真实数据不得加入 Git。
3. 在专用测试数据库执行增量迁移，验证重复执行、旧代码读取、角色策略、现有记录数量和状态。
4. 现有迁移入口读取 `server/schema.sql`；新增结构纳入该入口并提供受控迁移/恢复步骤，不能只放一份不会被执行的 SQL 文件。
5. 新功能先处于未启用状态。旧 `autoSelect=true`、旧质量分及浏览器默认同意不触发真实调用或自动上架。
6. 旧待审、驳回、下架记录保留。历史已发布作品只用可确认的已审核版本形成快照；若无法还原，暂停相关升级并列出人工确认项，不擅自公开当前新版本或删除旧记录。
7. 同步检查现有数据库行级权限和原始文档可读策略，确保通过公开快照展示，不因发布扩大私有文档访问。
8. 在测试库演练保存、服务重启、恢复及迁移后回归，通过后才准备目标环境操作。

### 7.3 回退办法

- 首先关闭 AI 审核、自动精选和自动发布，停止领取新任务；运行中任务允许留存结果，但提交前检查关闭状态，禁止继续发布。
- 保留所有作品、已审核快照、授权、任务与操作日志，不通过删表或清空数据实现回退。
- 先回退到兼容新字段、可人工审核的版本；若必须使用旧代码，先用适配迁移把新发布状态映射成旧接口可识别结果，并验证下架约束与快照仍有效。不得直接回退到仍读取原作品实时内容、会绕过快照的旧发布逻辑。
- 数据结构原则上保留新增列/表。恢复备份属于单独的数据恢复操作，必须评估并保护备份之后新增的作品，不能直接覆盖。
- 发布快照失效只能阻止之后访问，无法收回用户已经保存到本地的图片；界面撤下说明需准确。

## 10. 验收清单

所有验证必须记录日期、环境、步骤、结果及证据。测试数据与真实业务数据隔离；失败模拟必须标明，不能作为真实 AI 成功证据。

| 编号 | 必验场景 | 通过标准 |
|---|---|---|
| A01 | 设置保存、刷新、退出重登、后端重启 | 开关、文字、门槛和版本保持一致 |
| A02 | 自定义要求开启/关闭/重新开启 | 文字保留；仅开启时影响调用内容和结果 |
| A03 | 空要求、超长文字、负数/小数/越界门槛、失效模型 | 前后端都拒绝无效配置，原有效配置不丢失 |
| A04 | 两个管理员同时保存 | 检出冲突并提示，不静默覆盖 |
| A05 | 试审未保存规则 | 使用草稿、结果有版本说明、计额度、绝不上架 |
| A06 | 主动投稿与重复点击 | 一次有效提交，显示真实状态，失败保留可重试 |
| A07 | 合格最终版保存后关闭浏览器 | 服务端仍能完成自动精选，普通草稿不触发 |
| A08 | 安全通过但低于精选门槛 | 自动精选标记未入选；主动投稿不因此被驳回 |
| A09 | 自动上架开/关、AI 审核关闭 | 分别自动发布/待人工；AI 关闭无新增模型调用 |
| A10 | 真实 AI 看图成功 | 请求确实携带图片，响应被校验并落库；不是模拟返回 |
| A11 | 超时、429、余额不足、无视觉能力、空结果、格式错误、上游失败 | 不自动公开，不无限重试，有明确原因和下一步 |
| A12 | 日额度、多实例并发与重试 | 额度原子限制、调用次数可追踪、无重复任务上架 |
| A13 | 重启/处理中断/上游结果不明 | 任务可追踪恢复，不盲目重复付费 |
| A14 | 审核期间换最终版、改标题、删除作品 | 旧结果不能发布新内容，删除内容不展示 |
| A15 | 管理员下架、学生撤回、撤回授权 | 列表与图片访问同步失效；后台任务不能重新发布 |
| A16 | 原作品上架后继续修改 | 广场保留审核过的快照，新版本单独审核 |
| A17 | 未登录、学生、教师、家长、管理员、跨机构访问 | 管理权限受限，不能读取或操作别人的私有作品与审核记录 |
| A18 | 精确重复和可选近似检查 | 精确重复不重复发布；近似只提示复核，关开关后不执行附加检测 |
| A19 | 历史待审/驳回/下架记录及重复迁移 | 原数据不丢失、不自动转通过、不重复建任务 |
| A20 | 公开接口与真实浏览器广场 | 已发布作品可见、待审不可见，图片可读，状态与统计一致 |
| A21 | 桌面 1440×900、平板 1024×768、窄屏 390×844 | 输入框、开关、试审弹窗、表格及按钮无遮挡，键盘可操作 |
| A22 | 加载、空数据、成功、失败、禁用、未保存离开 | 各状态可识别；控制台无本次新增错误，失败请求不被隐藏 |

## 11. 启用步骤及停止条件

1. 首次只开放管理员试审，用少量已授权测试作品校准审核要求和精选门槛。
2. 小范围开启 AI 审核与自动精选，自动上架先关闭；管理员核对真实结果、误判及费用。
3. 达到验收标准且预算明确后，开启自动上架，只处理之后的新任务。
4. 上线前确认数据备份、后台任务启动与停止方式、日志脱敏、持久化目录、环境变量和部署回退步骤。
5. 发现越权、错误版本公开、下架后重新发布、费用失控、明显误判或任务持续失败，立即暂停自动发布/调用并保留证据，修复后重新验证。

暂停自动功能不应阻止学生保存作品和管理员处理待审。线上环境不可用时，只能交付“本地验收通过、线上待验证”，不能标记整体正式上线完成。
