SLOT · 画布节点 ↔ 学生端格子

老师搭好工作流模板后，不用逐个配置 slot。系统按画布从上到下自动数：第 N 个图像节点 = 学生端第 N 个图像格。
节点上的角标就是让你看得见这件事；只有想打乱顺序时，才在弹层里填一个数字（这就是全部的手工动作）。

3

实际会遇到的三件事，界面怎么处理

A. 新建模板：出厂就是对的

新模板自动铺 1 图像 + 1 文字 + 1 结果 ✓ 无需配置

文字节点默认就是「文字素材」，图像默认「图像」。老师新建完直接写提示词就行，一个角标都不用改。

B. 老师复制了一个文字节点当提示词用

复制出来的节点 不上前端 建议改标为「不上前端」

复制出来的文字节点默认不上前端。宁可少接一个，也不能让学生的一句话顶掉老师写死的整段提示词。

C. 发布前一行核对

发布前核对 学生端将显示：12 个图像框 · 1 个文字框 · 1 个结果 数字对不上 = 有节点忘了标
4

背后只多存两个字段

节点身上加，不改现有结构
字段取值作用
data.studentRole image / text / result / none 这个节点对学生端是什么。默认值按节点类型给，老师可改。
data.studentSlot 整数，或空 只在要打乱顺序时填。空着就按画布 position.y 从上往下数。

学生端提交时不再传 12 个固定格子，而是传 frames: [{ slot, imageUrl }]；服务端按 studentRole + studentSlot 把素材塞进对应节点，然后照常跑工作流。现有的 studentPage.blocks[].binding 机制本身就能用，只是把「谁绑定谁」从编辑器的隐藏字段搬到了节点上。
