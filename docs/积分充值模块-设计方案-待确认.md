## 一、这份方案解决什么

学生每次调用 AI 都要扣积分；积分能充值、能查余额、能查每一笔明细；老师/管理员能在后台给学生加分、生成积分码、改价格、看消耗。

一句话：**把「用一次 AI」变成「扣一次分」，并且每一分钱的去向都能查到。**

## 二、已锁定的参数（不再讨论）

| 项 | 值 | 说明 |
|---|---|---|
| 积分锚点 | **1 积分 = 0.1 元** | 10 元 = 100 积分，好算好记 |
| 加价倍率 | **2.0** | 定价 = 成本 × 2，毛利约 50% |
| 每日免费额度 | **60 分** | 当天清零，不累加，视频也参与 |
| 扣费方式 | **固定标价，点之前一次扣完，失败全退** | 不做冻结、不做结算、不做定时清理 |
| 归属类型 | **只有个人钱包** | 机构钱包留字段，本期不做 |
| 充值方式 | **信任制发码 + 后台人工加分** | 不接在线支付、不办商户号、不办备案 |
| 页面 | **零新增页面** | 全部落在现有「个人中心」和后台「账号权限」里 |

### 用户明确否决的方案

| 方案 | 为什么不用 |
|---|---|
| 冻结 → 结算 | 需要超时释放、差额对账、定时任务；固定标价下多余 |
| 按真实成本实时折算 | 每次分值跳动，家长看不懂，客诉多 |
| 月底统一结账 | 会欠账，要催收 |
| 机构钱包 / 机构积分 | 用户要求后期单独做机构后台 |
| 微信支付 / 支付宝直连 | 需营业执照与商户号；支付宝还要 ICP 备案，站点暂无域名 |
| 新开「家长端」「学生端」页面 | 已有个人中心 + 后台账号权限，再开端就是重复造页面 |

> **什么条件下重启「冻结→结算」**：如果以后开放学生自选视频时长（5s/10s/高清），成本差 3 倍以上，那一天视频单独改成冻结结算，图片继续固定价。这属于局部升级，不影响现在的代码。

## 四、五个概念，用大白话说

| 概念 | 大白话 | 对应数据 |
|---|---|---|
| 钱包 | 学生自己账上还有多少分，用不完可留到以后 | `credit_wallets` |
| 免费池 | 平台每天白送的 60 分，**当天用完清零，不进钱包** | `credit_daily_free` |
| 价目表 | 什么动作扣几分，后台随时可改 | `credit_prices` |
| 流水 | 每一笔加、扣、退的账本，只增不改，永远不删 | `credit_transactions` |
| 积分码 | 一串口令，家长拿到后在个人中心输入即可加分 | `redeem_codes` |

**为什么免费池不放进钱包**：若每天 60 分直接加到余额，家长会以为「我账上有 800 分，都是我买的」，实际一半是平台送的。分开记，钱包余额永远等于"真金白银充进来的钱"，对账清楚。

## 五、价目表（初始值，后台随时可改）

### 5.1 计价公式

```
单次积分 = 单次真实成本(元) × 倍率 2.0 ÷ 0.1
```

### 5.2 初始价目

| 动作标识 | 名称 | 假设成本 | 售价（2 倍） | **扣积分** | 60 分能换 |
|---|---|---|---|---|---|
| `image.generate` | 基础出图（1 张） | 0.25 元 | 0.50 元 | **5** | 12 张 |
| `image.generate.hd` | 高清出图（1 张） | 0.50 元 | 1.00 元 | **10** | 6 张 |
| `report.h5` | H5 报告（1 次） | 0.50 元 | 1.00 元 | **10** | 6 份 |
| `video.generate` | 视频（1 条） | 1.50 元 | 3.00 元 | **30** | 2 条 |
| `canvas.workflow` | 画布整页工作流（1 页） | 0.50 元 | 1.00 元 | **10** | 6 页 |

> 表中「假设成本」尚未用真实账单核实。上线两周后，系统会算出实际成本并给出建议价，改一个数字即可生效，代码不动。

### 5.3 改价不影响历史

流水里存的是**当时扣掉的分值快照**，不引用价目表。改价后老记录不会变，对账永远对得上。

### 5.4 2.0 倍率的安全垫

出图定价 5 分（0.5 元），成本 0.25 元。**成本要涨到 0.5 元（涨 100%），你才开始亏。** 这期间上游调价、失败重试，都不会让你亏钱。

## 六、扣费规则（核心逻辑）

### 6.1 扣款顺序

```
第 1 步：查今天免费池还剩多少
第 2 步：免费池够 → 全从免费池扣，钱包不动
第 3 步：免费池不够 → 免费池扣光，差额从钱包扣
第 4 步：钱包也不够 → 拒绝，提示「积分不足，还差 X 分」
```

例：今天要扣 30 分（视频），免费池剩 15 分，钱包有 100 分 → 免费池扣 15、钱包扣 15，钱包剩 85。

流水只记一条，但记录拆分（免费 15 / 钱包 15），对账时能看清。

### 6.2 失败怎么办

| 时机 | 动作 |
|---|---|
| 点生成、调用 AI 之前 | 先扣分，扣成功才发请求 |
| AI 返回成功 | 结束，不补不扣 |
| AI 返回失败/超时 | **全额退回**，按原路退（免费池扣的退免费池，钱包扣的退钱包） |
| 用户中途关页面 | 服务端仍等结果；失败即退，成功即算消费 |

### 6.3 三条防错底线

1. **同一任务只扣一次**：流水表对 `consume:{taskId}` 建唯一索引，重复请求被数据库直接拦下。
2. **余额永远不为负**：扣款时锁钱包行（`SELECT ... FOR UPDATE`）再判断，两人同时扣也扣不穿。
3. **前端传来的分值一律不采信**：服务端按价目表重算，前端报什么价都不看。

### 8.3 内部服务端函数（不对外暴露）

| 函数 | 作用 |
|---|---|
| `chargeCredits({orgId, userId, actionKey, taskId})` | 扣分，返回 `{ok, freeUsed, walletUsed}`，不足返回 `{ok:false, shortage}` |
| `refundCredits({orgId, userId, taskId})` | 按 taskId 全额退回，幂等 |

## 九、家长怎么付钱：信任制发码（本期主路径）

不接支付网关、不办商户号、不办 ICP 备案。走"你先信我、我记账"的路子。

### 9.1 全流程（家长视角 4 步）

```
第 1 步  家长打开「个人中心 → 积分充值」，选一个套餐（如 30 元 / 300 分）
第 2 步  页面立刻生成一张「待付款积分码」，同时显示收款二维码
         码长这样：MJ-7F3K-9QX2（30 元 · 300 分 · 生成于 20:14）
第 3 步  家长扫码付款（微信/支付宝均可），然后点「我已付款 · 去兑换」
第 4 步  自动跳到「我的积分」，码已自动填好 → 点「兑换」→ 300 分到账，
         流水立刻出现一行「充值 +300 · 来自积分码 MJ-7F3K-9QX2」
```

### 9.2 关键设计：先给码，后收钱

| 环节 | 谁在做 | 发生了什么 |
|---|---|---|
| 生成码 | 系统 | 码立刻可用（不等付款） |
| 付款 | 家长 | 微信/支付宝转账给你个人 |
| 兑换 | 家长 | 输入码 → 加分，即时生效 |
| 核对 | 老师（晚上） | 后台「今日核对」逐条勾「已收款」 |
| 没收到钱 | 老师 | 点「作废」→ 码失效 + 扣回已加的积分 |

**为什么敢先给码**：一个码只值 10–50 元，家长都是你班上的人。真赖账，作废即可，损失上限就是一次面额。这比办商户号、等备案快得多。

### 9.3 为什么不让系统"收到钱自动发码"

那需要支付平台回调你的服务器，等于要接微信/支付宝商户号 + 公网可访问的回调地址。这一步一办就是 1–2 周，而且站点还得有域名。**测试阶段不值得。**

### 9.4 后台「今日核对」怎么做

在后台「积分兑换码」页签下加一个筛选：`今天生成的 / 未确认收款的`，逐条显示：

| 码 | 面额 | 生成时间 | 谁兑换的 | 状态 | 操作 |
|---|---|---|---|---|---|
| MJ-7F3K-9QX2 | 30 元 · 300 分 | 20:14 | 李思远 | 已兑换 · **待确认收款** | `已收款` / `作废并扣回` |

晚上花两分钟点一遍，账面就对上了。

### 9.5 备用路径（等你有资质了再开）

| 路径 | 门槛 | 费率 | 什么时候用 |
|---|---|---|---|
| 信任制发码（本期） | 无 | 0 | 现在就可用 |
| 发卡平台代收 | 注册即可 | 2.8%–3.6% | 家长变多、不想手动核对时 |
| 微信支付 Native 扫码 | 个体户营业执照，1–2 工作日 | 0.6% | 想全自动到账时 |
| 支付宝当面付 | 个体户 + ICP 备案 | 0.6% | 不推荐，备案要 2–3 周 |

## 十一、每日 60 分的成本含义

60 分是**免费送给学生的额度**，不是学生付的钱。它的成本由平台承担：

| 60 分全部花在 | 能换 | 平台成本 |
|---|---|---|
| 基础出图（5 分/张） | 12 张 | 3.00 元 |
| H5 报告（10 分/份） | 6 份 | 3.00 元 |
| 视频（30 分/条） | 2 条 | 3.00 元 |

**所以 3 元/天 = 最坏情况下每个学生每天的成本上限。** 学生实际画不了 12 张。

按真实使用量估算：

| 每天实际出图 | 平台成本/天/人 | 100 个活跃学生/月 |
|---|---|---|
| 3 张 | 0.75 元 | 约 2250 元 |
| 6 张 | 1.50 元 | 约 4500 元 |
| 12 张（上限） | 3.00 元 | 约 9000 元 |

上线两周后系统会给出真实日均消耗，届时再决定 60 分要不要调。

| 家长付 | 孩子得到 | 能做多少 | 平台成本 | 毛利 |
|---|---|---|---|---|

| 30 元 | 300 分 | 60 张图 | 15 元 | 15 元 |

## 十三、验收标准

| 编号 | 验收标准 |
|---|---|
| AC-01 | 学生首次登录当天，`/api/credits/summary` 返回免费剩余 = 60 |

| AC-12 | 作废未收款码后，该码失效且剩余积分被扣回，流水新增一条 `void` |
| AC-13 | 导出「码表」每行一个码，「核对表」含面额/状态/兑换人/时间，两张表内容一致可对上 |

-- 1) 钱包：一个账号一个钱包
CREATE TABLE IF NOT EXISTS credit_wallets (
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  owner_type TEXT NOT NULL DEFAULT 'user' CHECK (owner_type IN ('user', 'org')),
  balance INTEGER NOT NULL DEFAULT 0 CHECK (balance >= 0),
  total_recharged INTEGER NOT NULL DEFAULT 0 CHECK (total_recharged >= 0),
  total_consumed INTEGER NOT NULL DEFAULT 0 CHECK (total_consumed >= 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (organization_id, user_id)
);

-- 2) 每日免费额度：当天一条，跨天新建一条（不累加）
CREATE TABLE IF NOT EXISTS credit_daily_quota (
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  grant_date DATE NOT NULL DEFAULT CURRENT_DATE,
  free_total INTEGER NOT NULL DEFAULT 60 CHECK (free_total >= 0),
  free_used INTEGER NOT NULL DEFAULT 0 CHECK (free_used >= 0),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (organization_id, user_id, grant_date),
  CHECK (free_used <= free_total)
);

-- 3) 流水：只增不改，所有余额变动都必须有一条
CREATE TABLE IF NOT EXISTS credit_ledger (
  id TEXT PRIMARY KEY,
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  direction TEXT NOT NULL CHECK (direction IN ('in', 'out')),
  amount INTEGER NOT NULL CHECK (amount > 0),
  from_free INTEGER NOT NULL DEFAULT 0 CHECK (from_free >= 0),
  from_wallet INTEGER NOT NULL DEFAULT 0 CHECK (from_wallet >= 0),
  kind TEXT NOT NULL CHECK (kind IN ('recharge', 'redeem', 'admin_adjust', 'consume', 'refund', 'void')),
  biz_type TEXT NOT NULL DEFAULT '',
  biz_id TEXT NOT NULL DEFAULT '',
  balance_after INTEGER NOT NULL DEFAULT 0,
  reason TEXT NOT NULL DEFAULT '',
  operator_user_id TEXT REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 4) 价目表：后台可改，改价不影响历史流水
CREATE TABLE IF NOT EXISTS credit_prices (
  id TEXT PRIMARY KEY,
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  code TEXT NOT NULL,
  label TEXT NOT NULL,
  credits INTEGER NOT NULL CHECK (credits >= 0),
  status TEXT NOT NULL DEFAULT 'enabled' CHECK (status IN ('enabled', 'disabled')),
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_by_user_id TEXT REFERENCES users(id),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (organization_id, code)
);

-- 5) 发码批次 + 6) 兑换码
CREATE TABLE IF NOT EXISTS credit_code_batches (
  id TEXT PRIMARY KEY,
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  face_value INTEGER NOT NULL CHECK (face_value > 0),
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  prefix TEXT NOT NULL DEFAULT '',
  note TEXT NOT NULL DEFAULT '',
  expires_at TIMESTAMPTZ,
  created_by_user_id TEXT REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS credit_codes (
  id TEXT PRIMARY KEY,
  organization_id TEXT NOT NULL REFERENCES organizations(id),
  batch_id TEXT REFERENCES credit_code_batches(id) ON DELETE CASCADE,
  code TEXT NOT NULL,
  face_value INTEGER NOT NULL CHECK (face_value > 0),
  status TEXT NOT NULL DEFAULT 'issued'
    CHECK (status IN ('issued', 'redeemed', 'confirmed', 'void')),
  order_no TEXT NOT NULL DEFAULT '',
  note TEXT NOT NULL DEFAULT '',
  issued_by_user_id TEXT REFERENCES users(id),
  redeemed_by_user_id TEXT REFERENCES users(id),
  redeemed_at TIMESTAMPTZ,
  confirmed_at TIMESTAMPTZ,
  confirmed_by_user_id TEXT REFERENCES users(id),
  expires_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (organization_id, code)
);

CREATE INDEX IF NOT EXISTS idx_credit_ledger_user_created
  ON credit_ledger(organization_id, user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_credit_ledger_biz
  ON credit_ledger(organization_id, user_id, biz_type, biz_id);
-- 幂等关键：同一笔业务（同 taskId）最多一条扣费流水
CREATE UNIQUE INDEX IF NOT EXISTS uq_credit_ledger_consume

  WHERE kind = 'consume' AND biz_id <> '';
CREATE INDEX IF NOT EXISTS idx_credit_codes_status

CREATE INDEX IF NOT EXISTS idx_credit_codes_batch ON credit_codes(batch_id);
CREATE INDEX IF NOT EXISTS idx_credit_wallets_org ON credit_wallets(organization_id, updated_at DESC);

-- 7) 默认价目（每个机构各一份，已存在则跳过）

## 16.2 第二步：新增 `server/credit-store.js`（服务层）

参照 `server/account-store.js` 的写法（`withUserContext` + `httpError`）。必须实现的函数：

| 函数 | 作用 | 关键实现点 |
|---|---|---|
| `ensureWallet(client, orgId, userId)` | 钱包不存在就建 | `INSERT ... ON CONFLICT DO NOTHING` |
| `ensureDailyQuota(client, orgId, userId, total=60)` | 当天额度不存在就建 | PK 是 `(org,user,grant_date)`，天然跨天重置 |
| `getSummary(user)` | 学生端余额总览 | 返回 `balance / freeTotal / freeUsed / freeRemaining / monthUsed / prices[]` |
| `listLedger(user, {limit=50, before})` | 流水分页 | 按 `created_at DESC` 游标 |
| `chargeCredits(user, { bizType, bizId, priceCode })` | **先免费后钱包**扣费 | 事务；`SELECT ... FOR UPDATE` 锁钱包；先查幂等唯一索引；`UPDATE credit_daily_quota SET free_used = free_used + x`；不够的部分从 `balance` 扣；写一条 `consume` 流水 |
| `refundCredits(user, { bizType, bizId, reason })` | 失败退款 | 找到对应 `consume` 流水，按 `from_free / from_wallet` **原路**退回；已退过直接返回 |
| `generateCodes(admin, { faceValue, quantity, prefix, note, expiresInDays, orderNo })` | 批量发码 | 字符集去掉易混字符（`0O1lI`）；`UNIQUE(org,code)` 撞了就重试 3 次 |
| `redeemCode(user, code)` | 学生/家长兑换 | 事务 + `FOR UPDATE` 锁码行；校验 `status='issued'`、未过期、未被别人绑；置 `redeemed` + 加钱 + 写 `redeem` 流水 |
| `adminAdjustCredits(admin, targetUserId, { delta, reason })` | 后台加减分 | `delta !== 0` 且 `reason` 非空，否则 400；扣分不得使余额为负 |
| `confirmCodePayment(admin, codeId)` | 今日核对「已收款」 | `status: issued → confirmed`，写 `confirmed_at/by` |
| `voidCode(admin, codeId, { clawBack })` | 作废码 | `issued → void`；若已兑换且要扣回，余额不足时**拒绝并提示先手动扣**（不产生负余额） |
| `listCodes(admin, filters)` / `exportCodes(admin, filters)` | 列表与导出 CSV | 两个视图：码表、核对表 |

**并发安全的写法（照抄这个模式）**：

```js
export async function chargeCredits(user, { bizType, bizId, priceCode }) {
  return withUserContext(user, async (client) => {
    // 1) 幂等：已有同业务扣费流水，直接返回，不再扣
    const existed = await client.query(
      `SELECT * FROM credit_ledger
       WHERE organization_id=$1 AND user_id=$2 AND biz_type=$3 AND biz_id=$4 AND kind='consume'`,
      [user.organization.id, user.id, bizType, bizId])
    if (existed.rows.length) return toChargeResult(existed.rows[0])

    // 2) 价格从库里取（后台改价立即生效，历史流水不受影响）
    const price = await getPrice(client, user.organization.id, priceCode)
    const amount = price.credits

    // 3) 锁钱包 + 当天的免费额度，顺序固定，避免死锁
    await ensureWallet(client, user.organization.id, user.id)
    await ensureDailyQuota(client, user.organization.id, user.id)
    const wallet = await client.query(
      `SELECT * FROM credit_wallets WHERE organization_id=$1 AND user_id=$2 FOR UPDATE`,
      [user.organization.id, user.id])
    const quota = await client.query(
      `SELECT * FROM credit_daily_quota
       WHERE organization_id=$1 AND user_id=$2 AND grant_date=CURRENT_DATE FOR UPDATE`,
      [user.organization.id, user.id])

    const freeLeft = quota.rows[0].free_total - quota.rows[0].free_used
    const fromFree = Math.min(freeLeft, amount)
    const fromWallet = amount - fromFree
    if (wallet.rows[0].balance < fromWallet) throw httpError('积分不足，请先充值。', 402)

    // 4) 一次性写：额度、钱包、流水
    if (fromFree) await client.query(
      `UPDATE credit_daily_quota SET free_used = free_used + $3, updated_at = now()
       WHERE organization_id=$1 AND user_id=$2 AND grant_date=CURRENT_DATE`,
      [user.organization.id, user.id, fromFree])
    const nextBalance = wallet.rows[0].balance - fromWallet
    if (fromWallet) await client.query(
      `UPDATE credit_wallets SET balance = balance - $3, total_consumed = total_consumed + $3, updated_at = now()
       WHERE organization_id=$1 AND user_id=$2`,
      [user.organization.id, user.id, fromWallet])

    const row = await client.query(
      `INSERT INTO credit_ledger (id, organization_id, user_id, direction, amount, from_free, from_wallet,
        kind, biz_type, biz_id, balance_after, reason, operator_user_id)
       VALUES ($1,$2,$3,'out',$4,$5,$6,'consume',$7,$8,$9,'',$3) RETURNING *`,
      [newId('cl'), user.organization.id, user.id, amount, fromFree, fromWallet, bizType, bizId, nextBalance])
    return toChargeResult(row.rows[0])
  })
}
```

## 16.9 风险与缓解

| 风险 | 缓解 |
|---|---|
| 家长兑了码但没付钱 | 「今日核对」当晚勾账；未收到就 `void` 作废并扣回 |
| 学生把码发给别人 | 码可绑定 `redeemed_by_user_id`，首次兑换即锁人；后台可查兑换人 |
| 余额被并发扣成负数 | 钱包行 `SELECT ... FOR UPDATE` + `CHECK (balance >= 0)` 双保险（AC-09） |
| 同一笔 AI 任务重复扣费 | `uq_credit_ledger_consume` 部分唯一索引兜底（AC-05） |
| 免费额度被无限刷 | 每日一条 `credit_daily_quota`，`CHECK (free_used <= free_total)` |
| 老师误加分 | 加减分必填原因，全量写 `admin_adjust` 流水，可追溯 |
